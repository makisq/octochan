# octochan

Минималистичный оркестратор для командной строки и CI. В основе — язык
сценариев со строгими типами, план до выполнения, заявки с согласованием,
откат, роли, серверный режим и слой для нейросетей (MCP и формальный
промпт).

Из коробки ochan работает с конфигурациями — файлами и живым
PostgreSQL/pgbouncer — и с исполнителем RLM. Это ниши, а не предел:
Linux, Ansible или что угодно ещё подключается источниками, исполнителями,
модулями команд и пакетами алиасов. ochan собирают под себя — от пары
алиасов до сложного оркестратора.

Версия — **0.1.0-alpha**: [что в ней](CHANGELOG.md).

## Быстрый старт

```bash
cd octochan
make install          # или scripts/install.sh; на Windows — scripts\install.ps1
ochan --version
```

`ochan` и `ochan-mcp` ставятся в `~/.local/bin` (на Windows — в
`%LOCALAPPDATA%\Programs\ochan`, он добавляется в `PATH`) и дальше
вызываются по имени из любого каталога, как `echo` или `python`.
Подробнее — [«Установка»](docs/guide/install.md).

Сравнить конфигурации по смыслу (`8GB` и `8192MB` равны):

```
$ ochan diff prod.conf test.conf
Найдены различия (2):
  max_connections: 100 -> 200 [Modified]
  log_min_duration_statement: — -> 1s [OnlyInRight]
```

Правка через заявку, с согласованием и откатом:

```
ochan plan prod.conf changes.conf            что изменится
ochan request prod.conf changes.conf         заявка «ждёт решения»
ochan approve 2fb5                           решение человека
ochan apply --request 2fb5                   ровно согласованное
ochan rollback 7a8f                          вернуть, как было
```

Сценарий на языке алиасов — проверка, план, заявка:

```
# rollout.ochan
var лимиты: map = {"db1": 200, "db2": 300, "db3": 150}
отчёт = file("rollout.log")
parallel for сервер in лимиты {
    try {
        c = config("base.conf")
        put(c, "max_connections", str(лимиты[сервер]))
        save(c, "out/" + сервер + ".conf")
        print(отчёт, сервер, "готов")
    } catch ошибка {
        print(отчёт, сервер, "ПРОПУЩЕН:", ошибка)
    }
}
```

```
ochan check rollout.ochan      ошибки до запуска, во всех ветках
ochan plan rollout.ochan       что запишется — ничего не записывая
ochan request rollout.ochan    согласование, затем apply --request и откат
```

Без аргументов на терминале `ochan` открывает интерактивную оболочку.
Ненулевой код возврата означает ошибку — команды пригодны для CI.

## Статус безопасности

Это альфа, и на что в ней можно рассчитывать, лучше знать заранее:

- **Песочница** (`--sandbox`) — две стены. Встроенные функции проверяют
  пути, окружение и живые источники, а на Linux сценарий ещё и выполняется
  отдельным процессом под ограничениями ядра: Landlock (файлы), seccomp
  (системные вызовы), свои пространства имён (пользователь, сеть). На macOS
  и Windows — отдельный процесс без окружения, а файлы и сеть держит только
  язык; ochan об этом предупреждает, `sandbox.strict: true` превращает
  предупреждение в отказ. Модули команд и языков — обычные исполняемые
  файлы, песочницей не ограничены; их защита — контрольная сумма.
- **Роли** локально защищают от ошибки и ограничивают нейросеть, но не
  владельца компьютера: кто может изменить `~/.octochan`, тот master. На
  общем сервере роли — граница между людьми: области, запреты, пределы,
  разделение обязанностей и журнал аудита с цепочкой хешей.
- **Серверный режим и MCP по HTTP** (вход, сессии, TLS, токены)
  независимого аудита не проходили. Не выставляйте их в недоверенную сеть
  и не используйте с боевыми паролями, пока код не посмотрит кто-то, кроме
  автора.
- **Не проверялось вживую:** исполнитель RLM работал только против
  поддельного API; тесты под Windows и macOS не запускались (только
  сборка); песочница ядра проверена на Linux 6.x x86-64, на arm64 — только
  сборка.

Единственное, на что альфа рассчитана твёрдо: нейросеть через `ochan-mcp`
не может ничего выполнить и согласовать — для этого нужен человек.
Подробнее — [«Безопасность»](docs/guide/security.md).

## Устройство

```
config  lang  arbiter  fp  i18n  logs  rbac  audit  sandbox  remote  pluginhost
scenario  pgsource  rlm  workspace  report  module  cmd     mcp/ — отдельный модуль
```

`config` не зависит ни от чего; СУБД и RLM — ниши, а не фундамент; ИИ —
модуль, а не основа. Подробно — [«Как устроен ochan»](docs/guide/concepts.md).
