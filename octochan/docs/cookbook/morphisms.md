# Две правки одного конфига: зависит ли итог от порядка

**Задача.** К боевому `prod.conf` готовят правки две команды: база
поднимает `shared_buffers`, приложение — `work_mem` и `max_connections`.
До выкатки нужно знать, что итог не зависит от того, чья правка придёт
первой. А `max_connections` должен уйти и в пул соединений перед базой,
`pgbouncer.ini`, — тем же изменением.

Правка здесь — не «поставь значение», а морфизм: преобразование одной
конфигурации в другую, которое помнит, с какого значения меняет. Морфизмы
композируются, и машина проверяет, коммутирует ли диаграмма, ещё до
записи. Синтаксис — в [руководстве](../guide/language.md#морфизмы-и-функторы).

## Исходное

```
$ cat prod.conf
max_connections = 100
shared_buffers = 1GB
work_mem = 4MB
$ cat pgbouncer.ini
[pgbouncer]
default_pool_size = 100
max_client_conn = 1000
```

## Сценарий

`выкатка.ochan`:

```
# Правки двух команд к боевому конфигу.
let база = {"shared_buffers": "1GB"} -> {"shared_buffers": "4GB"}
let приложение = morph({"work_mem": "64MB", "max_connections": "200"})

# Итог не должен зависеть от того, чья правка придёт первой.
let ab = база >> приложение
let ba = приложение >> база
if not commutes(ab, ba) {
    fail("правки зависят от порядка:", conflicts(ab, ba))
}
print(ab)

# Та же правка — для пула соединений перед базой.
let прод = config("prod.conf")
let к_пулу = functor({"max_connections": "pgbouncer.default_pool_size", "*": null})
if len(functor_laws(к_пулу, [база, приложение], [прод])) > 0 {
    fail("функтор нарушает законы")
}

save(ab(прод), "prod.conf")
save(к_пулу(ab)(config("pgbouncer.ini")), "pgbouncer.ini")
```

- `база` — морфизм `shared_buffers: 1GB -> 4GB`: он помнит, с какого
  значения меняет, и к конфигу с другим значением не применится.
  Описан по одному параметру, поэтому остальные параметры прода не
  трогает.
- `приложение` — `morph({…})`: задать значения, что бы ни стояло.
- `commutes(ab, ba)` сравнивает два пути символьно, без конфигов.
- `к_пулу` — функтор: переименовывает `max_connections` в
  `pgbouncer.default_pool_size` и забывает остальное (`"*": null`).
  `functor_laws` проверяет на данных, что он сохраняет тождество и
  композицию.

## План

```
$ ochan check выкатка.ochan
выкатка.ochan: ошибок не найдено
$ ochan plan выкатка.ochan
морфизм: max_connections = 200; shared_buffers 1GB -> 4GB; work_mem = 64MB

План: выкатка.ochan -> —

Изменений: 4

  prod.conf
    изменить   max_connections: 100 -> 200
    изменить   shared_buffers: 1GB -> 4GB
    изменить   work_mem: 4MB -> 64MB

  pgbouncer.ini
    изменить   pgbouncer.default_pool_size: 100 -> 200
```

## Если правки конфликтуют

Пусть приложение тоже трогает `shared_buffers`:

```
let приложение = morph({"work_mem": "64MB", "shared_buffers": "2GB"})
```

```
$ ochan plan конфликт.ochan
План: конфликт.ochan -> —
внимание: план неполный: сценарий прервался с ошибкой, показано то, что успело произойти
Изменений нет.
ошибка: конфликт.ochan:7:21: морфизмы не стыкуются: после первого shared_buffers = 2GB, второй ожидает 1GB
```

Конфликт пойман ещё на композиции: после правки приложения `shared_buffers`
уже не тот, с которого начинается правка базы. Ничего не записано, и код
возврата — 1, так что CI остановит выкатку. Если обе правки задают
значения без условий (`morph` с обеих сторон), композиция пройдёт, а
`conflicts` назовёт расхождение:

```
[shared_buffers: по первому пути 2GB, по второму 4GB]
```

## Заявка

```
$ ochan request выкатка.ochan
Вывод сценария в режиме плана:
морфизм: max_connections = 200; shared_buffers 1GB -> 4GB; work_mem = 64MB

Заявка 12c3c4122b создана (ждёт решения)
…
$ ochan approve 12c3c4122b
Заявка 12c3c4122b: согласована (root, роль master)
Выполнить: ochan apply --request 12c3c4122b
```

Пока заявка ждала выполнения, кто-то поставил в `prod.conf`
`shared_buffers = 2GB`. Морфизм `база` начинается с `1GB` и к такому
конфигу не применяется:

```
$ ochan apply --request 12c3c4122b
ошибка: сценарий прервался при повторном построении плана: выкатка.ochan:20:8: морфизм не применяется к конфигу prod.conf: ожидается shared_buffers = 1GB, в конфиге 2GB
```

Чужая правка не перезаписана молча: выполнение остановлено, и решать,
чья правка верна, будет человек. Когда `prod.conf` вернули к тому, что
согласовали:

```
$ ochan apply --request 12c3c4122b
Заявка 12c3c4122b, сценарий выкатка.ochan
морфизм: max_connections = 200; shared_buffers 1GB -> 4GB; work_mem = 64MB
Заявка 12c3c4122b выполнена, записано файлов: 2
Откат: ochan rollback 68042cc1c4
$ cat pgbouncer.ini
[pgbouncer]
default_pool_size = 200
max_client_conn = 1000
```

Морфизм, построенный от всего конфига (`config("prod.conf") -> config("желаемое.conf")`),
так не защищает: он требует только то, что меняет, а меняет всё, чем
текущий конфиг отличается от желаемого, — в том числе чужую правку.
Описывайте морфизм по параметрам, которые меняете.
