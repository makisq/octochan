# Нейросеть в оболочке: задача словами, заявка, проверка, выполнение

**Задача.** Не выходя из оболочки ochan, поручить модели задачу обычным
языком — «поставь work_mem = 32MB в pg.conf», — посмотреть сценарий и план,
которые она написала, и, если всё верно, согласовать и выполнить заявку.
Модель — внешняя: Claude, GigaChat или любой сервер с интерфейсом OpenAI.

Модель при этом может не больше, чем подключённая по MCP: читает файлы
только в своей папке, работает в роли `llm`, пишет сценарий, строит план и
оформляет заявку. Выполнить или согласовать её она не может — это делает
человек.

Строки ochan в рецепте настоящие: заявка, план, выполнение. Ответы модели —
от сервера-заглушки с интерфейсом OpenAI, который на задачу про `work_mem`
просит инструмент `request_script`; настоящая модель скажет своими словами.
С живыми Claude и GigaChat рецепт не прогонялся — для них нужен ключ
поставщика; их запросы проверены тестами на поддельных серверах.

## Настройка

```yaml
# config.yaml
llm:
  mode: natural              # задачи обычным языком
  chat:
    provider: anthropic      # anthropic | gigachat | openai
    model: claude-fable-5-2  # без модели — claude-opus-5-5
```

| Поставщик | Что задать |
|---|---|
| `anthropic` — Claude | `model` (по умолчанию `claude-opus-5-5`); `effort` — глубина размышлений: `low`, `medium`, `high`, `xhigh`, `max` |
| `gigachat` — GigaChat | `model` (по умолчанию `GigaChat`), `scope` (по умолчанию `GIGACHAT_API_PERS`), `ca` — корневой сертификат Минцифры |
| `openai` — сервер с интерфейсом OpenAI | `url` и `model`: сам OpenAI, локальный сервер модели (Ollama, vLLM, llama.cpp), шлюз |

Ключ в `config.yaml` не кладётся — его спрашивают без эха и хранят в
рабочем каталоге с правами 0600:

```
$ ochan auth --executor llm
Введите токен:
Ключ модели сохранён: ~/.octochan/tokens/llm — его читают ask и opmode llm
```

У GigaChat это ключ авторизации (Authorization key): токен доступа ochan
получает по нему сам и обновляет каждые полчаса. Вместо хранилища годится
переменная окружения: её имя — `llm.chat.key_env`, а без него —
`OPENAI_API_KEY`, `GIGACHAT_CREDENTIALS`; ключ Claude SDK берёт из
`ANTHROPIC_API_KEY` или профиля `ant auth login`.

У Claude при отказе модели по политике безопасности запрос перезапускается
на запасной модели на стороне Anthropic — это включено (`llm.chat.fallbacks:
true`); если ответила она, ochan говорит об этом строкой «(ответила запасная
модель …)». Выключить — `false`.

**Папка для модели.** Модель читает файлы только в папке, из которой запущен
ochan, а другие называет `llm.chat.root`. Папку, в которой лежит рабочий
каталог ochan, ей открыть нельзя — там роли и ключи. При установке в одну
папку (`ochan setup --here`) для этого создаётся подпапка `work`:

```
Файлы для нейросети: /srv/ochan/work — ask и opmode llm читают только её (config.yaml: llm.chat.root: [work])
```

## Одна реплика: ask

```
$ ochan ask поставь work_mem = 32MB в pg.conf
Пишу сценарий и оформляю заявку.
  → request_script {"name":"work_mem.ochan","script":"c = config(\"pg.conf\")\nput(c, \"work_mem\", \"32MB\")\nsave(c, \"pg.conf\")\n"}
Заявка оформлена. Вот что ответил ochan:
Заявка 1cc5ae2d97 создана (ждёт решения)
Изменений: 1

План: work_mem.ochan -> —

Изменений: 1

  /srv/ochan/work/pg.conf
    изменить   work_mem: 4MB -> 32MB

Согласовать: ochan approve 1cc5ae2d97
```

Строка со стрелкой — вызов инструмента ochan: видно, что модель делает.
`ask` — один вызов без истории; слова пишутся как есть, кавычки не нужны.

## Разговор: opmode llm

```
$ ochan shell
ochan[master]> opmode llm
Модель: Anthropic, claude-fable-5-2; инструментов ochan — 31, роль llm, изменения — заявкой
Режим нейросети: строка — реплика модели; команда ochan — с «?» в начале (?requests, ?apply --approve <номер>); выход — exmode llm
llm> поставь work_mem = 32MB в pg.conf
Пишу сценарий и оформляю заявку.
  → request_script {"name":"work_mem.ochan","script":"c = config(\"pg.conf\")\n…"}
Заявка оформлена. …
llm> ?search 1cc5
Заявки:
  2026-11-12 07:14  1cc5ae2d97  ждёт решения  сценарий work_mem.ochan, изменений: 1
План заявки: requests <номер>
llm> ?apply --approve 1cc5ae2d97
Заявка 1cc5ae2d97: согласована (ops, роль master)
Заявка 1cc5ae2d97, сценарий work_mem.ochan
Заявка 1cc5ae2d97 выполнена, записано файлов: 1
Откат: ochan rollback 196f536241
llm> exmode llm
Режим нейросети закрыт
ochan[master]> search pg.conf --in work
── work/pg.conf (39 Б, 12.11.2026 07:15) ──
max_connections = 100
work_mem = 32MB
```

- **Строка — реплика модели.** Разговор идёт с историей: «а теперь то же для
  server2» модель поймёт.
- **Команда ochan — с `?` в начале:** `?search`, `?requests 1cc5ae2d97`,
  `?apply --approve …`, инструкция языка — `?print("x")`. Точка с запятой в
  конце не мешает. Блок `?if … {` продолжается на следующих строках.
- **Выход — `exmode llm`** (можно `?exmode llm` и `exmode llm;`). `exit`
  выходит из оболочки совсем.
- **`apply --approve`** согласует и сразу выполняет: два шага одной командой,
  с правами обоих. Заявку нейросети согласуют, посмотрев план: команда
  спросит об этом, а с `--yes` — не спросит.
- **`search`** находит файл или заявку и показывает, что внутри
  ([«Текст и сеть»](../guide/text-net.md#поиск-search)).

## Без терминала

Режим работает и построчно — в конвейере, в CI, с вводом из файла:

```bash
printf 'opmode llm\nпоставь work_mem = 32MB в pg.conf\n?search work_mem\nexmode llm\n' | ochan shell
```

Конец ввода закрывает режим сам. Комментарии (`#`) модели не уходят.

## Чего модель не может

| | |
|---|---|
| Файлы | только в папке, из которой запущен ochan, и в `llm.chat.root`; рабочий каталог ochan закрыт |
| Роль | `llm`: читать, планировать, оформлять заявки; `apply`, `approve`, `!!install` — отказ самого ochan |
| Живые источники, переменные окружения, сеть сценариев | только разрешённые: `llm.chat.allow_live`, `allow_env`, `allow_net` |
| Сколько шагов подряд | `llm.chat.max_steps` обращений к модели на одну реплику (40) |

Содержимое файлов, которые модель читает, уходит её поставщику. Поэтому
право на `ask` и `opmode` — отдельная группа `ask`: у `master` она есть,
остальным ролям её выдают явно (`ochan role grant dba ask`).

## Если не получилось

| Сообщение | Что сделать |
|---|---|
| `модель для разговора не настроена` | задать `llm.chat.provider` и `llm.chat.model` |
| `в текущей папке лежит рабочий каталог ochan … нейросети она закрыта целиком` | держать файлы для модели в подпапке и назвать её в `llm.chat.root` |
| `llm.mode: embedded — своя модель знает только формальный промпт` | разговор ведёт внешняя модель: `llm.mode: natural` |
| `… не принял ключ (401)` | `ochan auth --executor llm` |
| `нет ochan-mcp` | поставить его рядом с `ochan` (`make install`, `ochan setup`) или назвать в `llm.chat.mcp` |
| `модель отказалась отвечать` | переформулировать задачу; причину отказа называет поставщик |
| `модель сделала 40 обращений подряд и не закончила` | задача слишком широкая — сузить её или поднять `llm.chat.max_steps` |

Модель, подключённая со стороны поставщика (Claude API с коннектором MCP,
ChatGPT, Gemini), — рецепт [«Модель в облаке и конфиги на своей
машине»](remote-llm.md); как она должна работать — [«Нейросети и
формальный промпт»](../guide/ai.md).
