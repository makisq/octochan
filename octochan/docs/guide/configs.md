# Конфигурации

## Команды

```
ochan diff prod.conf test.conf          сравнить две конфигурации
ochan validate postgresql.conf          проверить, что разбирается
ochan find postgresql.conf work_mem     найти параметр во всех секциях
ochan stats postgresql.conf             секции, параметры, замечания источника
ochan print prod.conf                   показать как есть (или stdin)
ochan patch prod.conf changes.conf -o patched.conf    перенести значения
ochan tee копия.conf                    продублировать stdin в файл
```

Форматы — `key = value` (conf, ini с секциями `[section]`), YAML, JSON и
ENV. Имя параметра в секции пишется через точку: `server.port`.

```
$ ochan diff prod.conf test.conf
Найдены различия (2):
  max_connections: 100 -> 200 [Modified]
  log_min_duration_statement: — -> 1s [OnlyInRight]

Отчёт сохранён: ~/.octochan/reports/diff_report_1.txt
Записано в историю: 3df8bb3cdb
```

`diff` сохраняет отчёт и пишет запись в журнал; `--fast` — только вывод в
консоль. Различие — не ошибка: код возврата 0. Чтобы CI падал на дрейфе,
см. рецепт [«Дрейф конфигурации в CI»](../cookbook/ci-drift.md).

`patch` переносит значения из `changes` в `base` и пишет результат в
файл `-o` (по умолчанию `patched.conf`); существующий файл без `--force`
не перезаписывается. Правка на месте — `-o prod.conf --force`: прежнее
содержимое попадает в журнал, и `ochan rollback` его возвращает. Новый
файл откатывать нечем — его просто удаляют. Что изменит `patch`, не меняя
ничего, — `ochan plan prod.conf changes.conf`.

## Сравнение по смыслу

| Равны | Не равны |
|---|---|
| `8GB` и `8192MB` | `1` и `on` |
| `1s` и `1000ms` | `8MB` и `8GB` |
| `on`, `true`, `yes` | `/var/lib/PG` и `/var/lib/pg` |

Размеры и длительности приводятся к общей единице, логические значения —
к одному виду. Пути и строки сравниваются как есть.

## Проверка значения

```
ochan if prod.conf max_connections '>=' 100 "лимит в норме"
ochan else prod.conf max_connections '<' 100 "поднимите лимит"
```

`if` и `else` — для интерактивной оболочки: `else` срабатывает, если не
сработал предыдущий `if`, а результат живёт в памяти процесса. В скриптах и
CI условие пишется на [языке алиасов](language.md): там есть и ветвление,
и `fail()` с ненулевым кодом возврата.

## Живой PostgreSQL

Везде, где команда принимает конфиг, можно указать живой сервер:

```bash
export PGPASSWORD=...        # либо ~/.pgpass — не в строке подключения
ochan diff эталон.conf postgres://dba@db1:5432/postgres
ochan stats postgres://dba@db1:5432/postgres
```

### Почему живой сервер, а не postgresql.conf

Для работающего PostgreSQL conf-файл не источник правды: поверх него
действуют `ALTER SYSTEM` (postgresql.auto.conf), директивы `include` и
параметры командной строки. Два сервера могут иметь одинаковые файлы и
вести себя по-разному. Поэтому читается `pg_settings`.

Значения пересчитываются в вид conf-файла. `pg_settings` хранит число в
единицах поля `unit`, и unit содержит множитель: для `shared_buffers`
сервер отдаёт `setting=16384` при `unit=8kB`, то есть 131072kB. Без
пересчёта сравнение с файлом давало бы расхождение в каждой строке.

Берутся только параметры, которые действительно являются конфигурацией:

| `source` | Что это | Почему не берём |
|---|---|---|
| `default` | ~300 параметров со значением по умолчанию | простыня «есть только справа» рядом с обычным conf-файлом |
| `override` | `config_file`, `data_directory`, `transaction_isolation` | факты рантайма, а не настройки |
| `client`, `session` | `application_name` и прочее от подключения | расхождение, которое создал сам инструмент |

`--all` (или `config(источник, "all")` в языке) отключает фильтр. Если
у параметра стоит `pending_restart`, об этом сказано отдельно:

```
внимание: изменены, но требуют перезапуска: max_connections, shared_buffers
Найдены различия (1):
  shared_buffers: 256MB -> 131072kB [Modified]
```

Здесь выполнили `ALTER SYSTEM SET shared_buffers = '256MB'` и перечитали
конфиг: файл уже говорит 256MB, а сервер работает на 128MB. Инструмент,
читающий только postgresql.conf, сказал бы «всё совпадает».

Подключение подписывается `application_name = octochan` — администратор
видит в `pg_stat_activity`, кто пришёл. Имя источника в отчётах, журнале и
ошибках пароля не содержит.

## Другие источники

Ядро не знает ни про PostgreSQL, ни про что-либо ещё: источник
регистрирует свою схему (`config.RegisterSourceScheme`, пример — пакет
`pgsource`). Новая система — новый пакет со схемой, а не правка ядра.
