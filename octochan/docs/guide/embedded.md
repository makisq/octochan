# Своя модель: режим embedded

У ochan три режима модели. Они отличаются тем, где стоят кольца и какой язык
модели доступен:

| Режим | Модель | Задачи и ответы | Кольцо 0 | Отвергнутое в ответе |
|---|---|---|---|---|
| `protocol` | внешняя, по MCP | формальный промпт | нет | есть, но дальше не проходит |
| `natural` | внешняя, по MCP | естественный язык | нет | есть, но дальше не проходит |
| `embedded` | локальная, по протоколу движка v1 | **только** формальный промпт | внутри генерации | **нет** |

В `protocol` модель пишет ответ сама, а кольца 1–3 и арбитр читают готовый
текст: отвергнутое утверждение в ответе есть, оно только не проходит дальше.

В `embedded` подход зависит от того, чья модель, а не от того, где она
стоит:

- **Своя модель ℒ** (`llama/own.py`) — архитектурная, и режим у неё один:
  логика и кольца в её коде, ответ она пишет целиком сама, ochan проверяет
  его снаружи ([«Архитектурная модель»](#архитектурная-модель)).
  Настройки декодера `llm.decoder.*` к ней не применяются: её параметры —
  `rings.json` рядом с весами.
- **Чужой движок** — сеть без логики в коде, которая отдаёт только
  распределение следующего токена (дообученная на fp модель
  `llama/train.py`, демонстрационный движок), — её генерацию ведёт декодер
  ochan. Это протокольный подход на своей машине: ochan видит
  распределение и не даёт модели напечатать то, что не прошло кольцо 0
  или не принадлежит языку. Отвергнутого в ответе нет вообще.

Какой подход, ochan узнаёт у движка (`/v1/info`: у своей модели
`"generate": true`) и пишет в `ochan llm`. Движок, не подтвердивший
протокол, генерации не получает.

Модель в `embedded` знает только формальный промпт. Говорить на
естественном языке она не может: ни в ответе, ни в письме, ни в записи
инцидента.

## Настройка

```yaml
# ~/.octochan/config.yaml
llm:
  mode: embedded            # protocol | embedded | natural
  endpoint: http://127.0.0.1:8093
  model: ~/models/own       # каталог своей модели: его загружает адаптер, не ochan
  timeout: 60s
  adapter:                  # адаптер запускает ochan (ochan llm serve)
    python: ""              # пусто — venv рядом с adapter.py, иначе python3
    script: ""              # пусто — adapter.py, который поставил make install-llm
    device: ""              # cuda | cpu; пусто — видеокарта, если она есть
    autostart: true         # llm generate и llm run запустят адаптер сами
    restarts: 5             # перезапусков упавшего подряд
    start_timeout: 180s     # сколько ждать, пока модель загрузится
  decoder:                  # декодер ochan — только для чужого движка
    tau: 0.42               # кольцо 0
    max_tokens: 2048        # сколько раз спросить модель за ответ, с откатами
    retries: 32             # откатов на одно утверждение
    derive: true            # выводимое из посылок пишет логика, модель — только выбирает
```

Прежние ключи `llm.rings.tau`, `llm.max_tokens`, `llm.retries`,
`llm.derive` читаются, пока нового нет в конфиге; `ochan llm` говорит, как
ключ называется теперь. Если настройки декодера заданы не по умолчанию, а
за адресом своя модель, `ochan llm` и `llm generate` предупреждают: она их
не читает.

```
$ ochan llm
Режим:   embedded (своя модель — логика и кольца в её коде; чужой движок ведёт декодер ochan: кольцо 0, τ=0.42 — на позицию не больше 2 токенов)
Движок:  http://127.0.0.1:8093 — протокол v1, transformers, модель ~/models/own
Подход:  архитектурный — своя модель ℒ: логика и кольца в её коде, ответ она пишет сама, ochan проверяет его снаружи
Кольца:  параметры модели — rings.json рядом с весами (llama/fit.py, llama/learn.py)
Знания:  пакетов знаний модель не видит (adapter.py serve --modules ~/.octochan/modules)
Модель:  ~/models/own (её получает адаптер: ochan llm serve)
Язык:    только формальный промпт: в ответе модели — утверждения ℒ, ничего на естественном языке
```

Адаптер не запущен — `ochan llm` говорит, как его запустить:

```
Движок:  http://127.0.0.1:8093 — движок http://127.0.0.1:8093 недоступен: Get "http://127.0.0.1:8093/v1/info": dial tcp 127.0.0.1:8093: connect: connection refused
Запуск:  llm generate и llm run запустят адаптер сами (llm.adapter.autostart); держать его постоянно — ochan llm serve
```

Без `llm.mode` режим берётся из прежнего `fp.mode`: `natural` → `natural`,
иначе `protocol`. Сочетание `llm.mode: embedded` и `fp.mode: natural` —
отказ:

```
$ ochan llm
ошибка: llm.mode: embedded и fp.mode: natural вместе нельзя: встроенная модель знает только формальный промпт
```

## Запуск: адаптер своей модели

Модель загружает и держит в памяти адаптер — `llama/adapter.py`, процесс
рядом с ochan ([«Протокол движка v1»](#протокол-движка-v1)). Ставит его
установка, запускает и перезапускает — сам ochan.

**Установка.** Адаптер ставится рядом с ochan, вместе с окружением Python
по `llama/requirements.txt`:

```
make install-llm                                   # Linux, macOS: share/ochan/llm, venv в нём
TORCH_INDEX=https://download.pytorch.org/whl/cu128 make install-llm   # torch для видеокарты NVIDIA
scripts\install.ps1 -Llm -TorchIndex https://download.pytorch.org/whl/cu128   # Windows: <Bin>\llm
```

```
Адаптер своей модели: /usr/local/share/ochan/llm/adapter.py; в config.yaml — llm.model (каталог модели) и llm.endpoint, запуск — ochan llm serve
```

Весов в репозитории нет: модель обучают на своей машине
(`llama/train_own.py`, [README своей модели](../../llama/README.md)) и
указывают каталог с весами в `llm.model`. Без видеокарты обучение и
адаптер работают на процессоре (`--device cpu`, `llm.adapter.device: cpu`).

**`ochan llm serve`** запускает адаптер с `llm.model` на адресе
`llm.endpoint`, ждёт, пока модель загрузится и ответит на `/v1/info`, и
сверяет, что отвечает та модель, что в `llm.model`:

```
$ ochan llm serve
Адаптер: /usr/local/share/ochan/llm/venv/bin/python /usr/local/share/ochan/llm/adapter.py serve --model ~/models/own --listen 127.0.0.1:8093 --modules ~/.octochan/modules --device cpu
Журнал:  ~/.octochan/logs/adapter.log
Адаптер: http://127.0.0.1:8093, протокол v1, модель ~/models/own, своя, архитектурная
Адаптер готов: http://127.0.0.1:8093 — модель ~/models/own, pid 7783
```

- Упавший адаптер перезапускается с растущей паузой. Упал
  `llm.adapter.restarts` раз подряд, не проработав минуты, — ochan
  сдаётся: модель, которая падает при загрузке, перезапуском не починить.
- Вывод адаптера — в терминал и в `~/.octochan/logs/adapter.log`.
- Ctrl+C или SIGTERM останавливают адаптер: сначала SIGTERM, через 5 с —
  принудительно (на Windows — сразу).
- По адресу уже кто-то отвечает — второй адаптер `llm serve` не
  запускает. Отвечает модель не из `llm.model` — об этом предупреждают
  `ochan llm` и `llm serve`.

С `llm.adapter.autostart: true` держать `llm serve` не нужно: `llm
generate` и `llm run` сами запускают адаптер, если он не отвечает, и
останавливают его, когда закончат.

## Как ochan ведёт чужую модель

Этот раздел — о чужом движке. Свою модель ochan по токенам не ведёт: она
отвечает сама ([«Архитектурная модель»](#архитектурная-модель)).

```
движок → распределение следующего токена (top ⌊1/τ⌋ кандидатов и конец ответа)
       → кольцо 0: токен с p < τ не берётся
       → маска языка: комментарий, символ вне ASCII, табуляция — не берутся
       → строка дописана — это утверждение: проверка языка ℒ
           не в языке → откат к началу утверждения, токен, на который
           указала находка, запрещён на своём месте
       → конец ответа — проверка текста целиком; не сложился — конец запрещён
```

- **Кольцо 0.** Из кандидатов выше порога выбирается самый вероятный (выбор
  детерминирован). Больше ⌊1/τ⌋ токенов порог не пройдёт никогда
  (`rings.MaxPass`), поэтому движок отдаёт только их, а не весь словарь.
  При τ = 0,42 на позицию проходит не больше двух.
- **Утверждение — строка.** Разбор языка построчный, и строка — наименьшая
  часть текста, которую можно проверить, не зная продолжения. Находки,
  которые снимет продолжение (пустой раздел в конце, цель, класс которой ещё
  не объявлен), строку не останавливают.
- **Откат.** При том же тексте модель дала бы то же распределение, поэтому
  генерация откатывается к началу утверждения, и путь, который увёл из
  языка, запрещён: со второго раза модель идёт другим. Позиция, где порог не
  прошёл ни один разрешённый токен, снимает ещё один токен назад. Если
  кольцо 0 пусто в самом начале утверждения, ответа нет: модель не уверена
  ни в одном продолжении.
- **Средний логарифм вероятности** токенов каждого утверждения сохраняется:
  это β₁ правила выбора между пакетами (`rings.Choose`).

Кольца 1–3 и арбитр работают как прежде, по плану сценария: в `embedded`
меняется не то, *как* проверяется план, а то, *что* модель вообще может
написать.

### Что пишет не модель

Ответ на задачу (`--prompt`) — та же программа, закрытая там, где задача
оставила открытым. Большую его часть модель не пишет:

- **Копию задачи пишет ochan** — в канонической записи: без комментариев,
  одиночные пробелы, не больше одной пустой строки подряд. Это текст
  оператора, и переписывать его модели незачем: ошибка копирования портила
  бы весь ответ.
- **Выводимое из посылок пишет логика** (`llm.decoder.derive`, по умолчанию
  включено). Единица здесь — пакет, утверждение целиком. Логика (`fp.Derive`)
  выводит решения из точных посылок: отношение `defines`, `limits` или
  `modifies` переносит атрибут источника на цель без него — цепочкой:
  выведенное значение — посылка для следующего шага (A → B → C); другой
  путь с другим значением, которое приоритет не снимает, — вопрос
  оператору; конфликт источников решает приоритет; атрибут обобщения —
  схемы отношения переходит на его стрелки-частные случаи без него, но не
  на слот. На каждом месте
  ответа логика называет допустимые утверждения: одно — его пишет декодер,
  несколько — модель только выбирает среди них (`/v1/score`), ни одного —
  ответ кончается. Сейчас выбор остаётся только в порядке решений внутри
  ячейки; остальное следует из посылок и уже написанного.
- **Конфликт без приоритета — вопрос оператору**: посылки не выбирают между
  значениями, и ни логика, ни модель решения не пишут —
  `Вопрос оператору: …` в stderr.

Сводка показывает, сколько утверждений написала логика и сколько выбрала
модель:

```
Логика:      утверждений 11 — единственные допустимые; выбрано моделью среди допустимых: 1
```

С `llm.decoder.derive: false` решения пишет модель по токену, как раньше;
копию — всё равно ochan.

### Архитектурная модель

Формальное промптирование работает двумя способами. **Протокольный** —
для внешних моделей (через API и MCP): язык, кольца, логика и арбитр
стоят вокруг модели, в её код не попасть. **Архитектурный** — своя модель
ℒ (`llama/own.py`): логика, кольца, отказ без предпосылки, поддержка
правил и калибровка — часть её кода, как веса. Её функция распределения
переопределена: следующий токен вне допустимых логикой утверждений имеет
вероятность ноль.

Режим у своей модели один — этот. Пошагового режима с декодером ochan у
неё нет: её распределение и так переопределено её логикой, а второй слой
той же логики снаружи только дублировал бы первый и вводил настройки,
которые на неё не действуют. Сеть без логики и колец — только для замера
(`adapter.py raw`, `measure.py`), не режим работы.

Такая модель отвечает целиком сама (`/v1/info` говорит `"generate": true`,
ответ — `POST /v1/generate`; без задачи — `--prompt` — ей отвечать не на
что), и ochan её не ведёт, а проверяет снаружи:

- ответ в языке и начинается канонической копией задачи;
- каждое решение выводимо из посылок (`fp.Derive`), пропущено только то,
  что её кольцо 2 не приняло, — это вопросы оператору;
- сужение по истории — внутри неточной предпосылки, и без второго
  значения того же вопроса отчёта.

У решения в цепочке правила — весь его путь (`fp.defines`, затем
`fp.modifies`), и кольцо 1 модели перемножает их надёжность. Без журнала
(условный счёт 8 из 8, [0,66; 1,00]) у цепочки из двух шагов нижняя
граница около 0,44 — ниже порога 0,5, и такое решение уходит оператору,
пока журнал его правила не подтвердит.

```
Архитектурная модель: ответ написала она сама — логика и кольца в её коде; ochan проверил его снаружи
Логика:      утверждений 9 — единственные допустимые; выбрано моделью среди допустимых: 0
Журнал решений: запись c485b14c29; исход — ochan fp journal amend c485b14c29 --right | --wrong --reason …
```

Ответ уходит в журнал решений с правилами, поддержкой и точными
посылками задачи. Исход отмечает оператор — `ochan fp journal amend`, — и
из журнала модель пересчитывает свои параметры, как обучение — веса:

```
ochan fp journal export > journal.json
python llama/fit.py --model ./models/own --journal journal.json
```

`fit.py` пишет `rings.json` рядом с весами: надёжность правил вывода
(`fp.defines`, `fp.limits`, `fp.modifies`, `fp.arrow`), историю
прочтений атрибутов, веса правила выбора и монотонную калибровку — две
последние, когда исходов выбора хватает.

Второй источник параметров — повторяющиеся инциденты. Созревшие кластеры
`ochan incident learn --export` (раздел «Обучение на повторяющихся
инцидентах» в [HA-AI](ha-ai.md)) модель берёт в `rings.json`:

```
ochan incident learn --export ripe.jsonl
python llama/learn.py --model ./models/own --clusters ripe.jsonl
```

У кластера — обобщение (структура без частных имён) и надёжность правил
на этой структуре по исходам его инцидентов. Задачу той же структуры
модель узнаёт сама, и кольцо 1 берёт надёжность по кластеру, а не в
среднем по журналу: правило, верное в среднем, на структуре, которую
модель решает плохо, кольцо 2 не пропускает, и задача уходит оператору.
ochan пишет, какой кластер узнала модель, и ключ кластера — у пакета в
журнале:

```
Кластер:     75cf2d265cfe — задача повторяет структуру 8 инцидентов; модель решила сама 1.0 из 5.8, надёжность [0.39; 0.84]
```

Знания модели годятся и другим машинам: `learn.py --package` выгружает
кластеры пакетом знаний реестра — обобщения и надёжность правил на них, без
номеров инцидентов, — а модель там берёт их для задачи с
`import @пакет v…` ([«Пакет знаний»](modules.md#пакет-знаний)). Адаптер
читает пакеты из каталога модулей ochan:
`adapter.py serve --model ./models/own --modules ~/.octochan/modules`;
`ochan llm` показывает, какие знания видит модель.

Каждая запись `rings.json` — новая версия в `rings.versions/`:
`learn.py --versions` — список, `learn.py --rollback [N]` — откат. Сеть
можно дообучить на парах кластеров с примесью базового корпуса
(`learn.py --pairs`, `train_own.py --init`): новые веса — в новый каталог,
прежние остаются для отката.

### Неточные предпосылки

Значение задано, но размыто — множество прочтений или диапазон
(раздел 5.2 манифеста):

```
cell c1:
  set File.window = night
  set Approval.window = {night, weekend}
  set Restart.window = {night, weekend}
  set Pool.size = 100..500
```

Неточное само ничего не переносит. Сузить его можно только внутри и
только по источнику, с записью в отчёт:

- **точной посылкой через отношение** — `File.window = night` и
  `File --defines--> Approval` сужают `Approval.window` до `night`,
  `basis: relation(…)`; значение вне множества — вопрос оператору;
- **историей прочтений** — так делает архитектурная модель по журналу:
  как оператор задавал этот атрибут точно в прошлых задачах и какие
  сужения одобрил. Лидер сужает, только если нижняя граница его доли выше
  верхних границ остальных; иначе варианты сопоставимы и решает оператор:

```
cell c2:
  set Restart.window = night

report:
  q: window
    choice: night
    alternatives: {night, weekend}
    basis: history(window)
```

Без источника модель не угадывает:
`Вопрос оператору: set Restart.window = {night, weekend}; неточная
предпосылка: сузить её нечем — ни посылки, ни истории`.

## Цикл агента: ochan llm run

Внешняя модель сама вызывает инструменты MCP. Своя модель ℒ отвечает
только формальным промптом, и в действия её ответ переводит ochan —
`ochan llm run`. Действия идут командами ochan от роли `llm` и агента: с
их правами, пределами, журналом аудита и той же проверкой языка, что у
любой модели.

| Задача | Ответ принят | Ответа нет |
|---|---|---|
| открытый инцидент на хосте агента | заметка к инциденту; со сценарием — заявка, под free выполнена — инцидент решён | эскалация инженерам с причиной |
| письмо в ящике агента | ответ отправителю (`mail send --reply`) | отправителю — причина |
| `--prompt задача.fp` | ответ в stdout; со `--scenario` — заявка | причина в stdout, код возврата 1 |

**Ответа нет** — задача не на языке, без предпосылки (⊥undef), отказ
модели, вопрос оператору или ответ, который ochan не принял. Причина —
тоже формальным промптом: `Failure.error` — недостающие предпосылки,
`Failure.check` — вопросы оператору, `Failure.fault` — что не так с
задачей или ответом.

```
$ ochan llm run --prompt undef.fp
не хватает предпосылок (⊥undef): load_model: такого отношения нет ни в промпте, ни в скиллах — система не достраивает его сама (П5)
goal: failure

classes:
  Failure : "failure"

cell c1:
  set Failure.error = load_model
ошибка: ответа нет — причина выше, формальным промптом
```

**Из решения — заявка.** Как решение задачи становится изменением
системы, модель не решает и ochan не угадывает: перенос структуры задачи в
структуру реализации манифест сознательно не автоматизирует (вопрос 14).
Это делает сценарий исполнителя, который пишет оператор, — с местами
`${Класс.атрибут}`. Решённые значения ответа подставляются в эти места, и
сценарий становится заявкой с `--incident`. Места без значения в ответе —
вопрос оператору, а не заявка с пустым местом.

Сценарий прикладывают к инциденту — `incident open --scenario`, поле
`scenario` вебхука `POST /v1/incidents` — или к задаче:
`llm run --prompt задача.fp --scenario сценарий.yaml`. Без сценария
решение уходит людям: заявку оформит человек.

Пример — контур HA-AI, агент db7 под free с политикой `fix-db`
([«HA-AI, free и инциденты»](ha-ai.md)):

```
$ cat realize.yaml
service: demo
parameters: {max_connections: "${Config.max_connections}"}
targets:
  - group: db_new

$ ochan incident open --level critical --host db7 --scenario realize.yaml "$(cat task.fp)"
Инцидент 96a7460e77 (critical) открыт: модель чинит сама до 12:55 (15m)

$ ochan llm run --agent db7 --once
Агент db7: модель ~/models/own; задачи — письма и инциденты на хосте db7
Инцидент 96a7460e77 (critical)
  ответ модели — заметкой
  заявка fb4f74ef60 выполнена без человека (free)
  инцидент решён

$ ochan incident 96a7460e77
…
Шаги:
  12:40:18  master     open: goal: tuned …
  12:40:18  llm        note: goal: tuned …
  12:40:19  llm        request fb4f74ef60: demo через Demo, операций: 1
  12:40:19  deployer   apply fb4f74ef60: выполнена
  12:40:19  llm        resolve: goal: tuned …
```

Модель вывела `Config.max_connections = 300` из посылки задачи
(`Limit --modifies--> Config`), значение легло в сценарий, заявка уложилась
в политику и выполнилась от роли `deployer` без человека. Копия
сценария, каким его получила заявка, — в
`~/.octochan/llm/agents/db7/96a7460e77.yaml`. Без сценария тот же ответ
становится заметкой, а инцидент — эскалацией:

```
Инцидент 7f71fccaff (medium)
  ответ модели — заметкой
  эскалирован инженерам: к инциденту не приложен сценарий: решение есть, заявку оформит человек
```

На письмо модель отвечает отправителю; его имена — имена задачи ответа:

```
$ ochan llm run --agent db7 --once
Агент db7: модель ~/models/own; задачи — письма и инциденты на хосте db7
Письмо e87f2a9994 от llm, агент db8
  ответ → db8
```

Без `--once` цикл ходит каждые `--every` (30 с), пока его не остановят; на
standby он ждёт — задачи берёт primary. Что агент уже обработал, — в
`~/.octochan/llm/agents/<агент>.json`: письмо и инцидент берутся один раз.

## Протокол движка v1

Локальная модель подключается **адаптером** — отдельным процессом рядом с
моделью (`llama/adapter.py`). ochan говорит с ним по HTTP и сначала сверяет
протокол (`/v1/info`): движок недоступен или говорит по другой версии —
генерации нет. Своя модель отвечает целиком (`/v1/generate`), чужой движок
ochan ведёт по токенам:

```
GET  /v1/info  → {"protocol": 1, "engine": "transformers", "model": "~/models/own", "generate": true}
POST /v1/generate ← {"prompt": "…"}
                  → {"answer": "…", "refused": false, "missing": […], "questions": […], "forced": 9, "chosen": 0}
POST /v1/next  ← {"prompt": "…", "output": "…", "top": 2}
               → {"candidates": [{"text": "goal", "p": 0.81}, …], "end": 0.001}
```

- `prompt` — неизменная часть: протокол и задача. Адаптер держит её в кеше и
  досчитывает только `output`, ответ до этого места.
- `top` — сколько кандидатов нужно: ⌊1/τ⌋.
- `p` — вероятность токена в **полном** распределении модели, после softmax и
  до любой выборки: температура, top-p и штрафы адаптера её не трогают.
  `end` — вероятность конца ответа. Кандидаты — по убыванию `p`, в сумме с
  `end` не больше единицы: иначе ochan отказывает («это не распределение»).
- `output` может кончаться не на границе токена модели: после перевода
  строки ochan спрашивает заново с текста, кончающегося на `\n`.

Где логика оставила выбор из нескольких утверждений, модель оценивает
каждое целиком:

```
POST /v1/score ← {"prompt": "…", "output": "…", "continuations": ["  set A.x = 1\n", …]}
               → {"scores": [{"logp": -0.21, "tokens": 7}, …]}
```

`logp` — сумма log p токенов продолжения после `prompt` + `output` в том же
полном распределении, `tokens` — их число; порядок — как в запросе. Движок
без `/v1/score` годится, пока выбора нет; иначе ответа нет с причиной.

Пример адаптера и сервер протокола — `examples/embeddedengine` и
`embedded.Handler`. Адаптеру остаётся реализовать `Engine.Next` и, для
выбора, `Scorer.Score`.

### Адаптер — для одной машины

У адаптера нет аутентификации и TLS: он для той же машины, что ochan.
`llama/adapter.py` слушает только локальный адрес; не локальный —
отказ до загрузки модели, а с `--allow-remote` — только за прокси с TLS и
аутентификацией. Тело запроса — не больше 1 МиБ (протокол — около 16 КиБ,
задача — единицы КиБ), без `Content-Length` — отказ; клиент, который не
прислал тело за 60 с, отключается: сервер однопоточный, и один зависший
запрос не должен держать модель.

## Проверить без модели

Демонстрационный движок (`examples/embeddedengine`) знаний не имеет. Он ведёт
к ответу из файла и по дороге пробует заговорить, как слабая модель: в начале
одной строки — по-английски, в начале другой — по-русски, и в этом он уверен
больше, чем в ответе. Рецепт целиком — [«Своя модель без модели»](../cookbook/embedded-demo.md).

```
$ ./embedded-demo --answer answer.fp --listen 127.0.0.1:8090 \
    --chatter "13=Sure, here is what I found" --chatter "14=Готово, вот что я нашла"
Демонстрационный движок: http://127.0.0.1:8090, протокол v1; ответ — answer.fp; знаний у модели нет

$ ochan llm
Режим:   embedded (своя модель — логика и кольца в её коде; чужой движок ведёт декодер ochan: кольцо 0, τ=0.42 — на позицию не больше 2 токенов)
Движок:  http://127.0.0.1:8090 — протокол v1, ochan-demo, модель demo (answer.fp)
Подход:  протокольный — чужой движок ведёт декодер ochan: кольцо 0, τ=0.42; выводимое из посылок пишет модель (llm.decoder.derive: false)
Язык:    только формальный промпт: в ответе модели — утверждения ℒ, ничего на естественном языке

$ ochan llm generate --prompt task.fp
Утверждений: 2, токенов: 12, обращений к модели: 20
Кольцо 0:    отклонено 11 (токенов до порога τ=0.42)
Язык:        утверждений вне ℒ 1, токенов вне языка 1 — в ответе их нет
Откатов:     1 к началу утверждения; позиций без токена выше порога: 0
goal: connection

classes:
  Connection : "connection"
  Limit : "limit"
  Node : "host"

relations:
  Limit --limits--> Connection (connection_cap)

cell c1:
  set Limit.max_connections = 200

cell c2:
  set Connection.max_connections = 200
```

«Sure, here is what I found» модель собрала целиком: строка не в языке, и её
нет в ответе. «Готово» отвергнуто на первом же токене маской языка. Ответ —
в stdout, сводка колец — в stderr, поэтому ответ можно сразу отправить:
`ochan llm generate --prompt task.fp | ochan mail send --prompt task.fp --to operators -`.
`--prompt` — задача оператора. Задачу не на языке модель не получит. Задачу
без предпосылки — тоже: недостающее (⊥undef — требование, операция,
скилл, обобщение, которых нет в задаче и в библиотеке) ochan возвращает
сам, вопрос уходит оператору. Догадаться модели не из чего, и отказ не
зависит от того, чему она выучилась (П5, раздел 5.2 манифеста).

В журнале решений появляется кольцо 0. В `protocol` этой строки нет, и по
отчёту видно, что гарантии другие:

```
$ ochan fp journal
Режим: embedded (своя модель — логика и кольца в её коде; чужой движок ведёт декодер ochan: кольцо 0, τ=0.42 — на позицию не больше 2 токенов)
Отклонено на кольце 0: 11 (токенов до порога); генераций 1, с ответом 1
Отклонено языком:      2 (утверждений и токенов вне ℒ — в ответах их нет)
Отклонено на кольце 2: 0 (нижняя граница < well_True)
Отклонено на кольце 3: 0 (противоречие)
```

`ochan fp check` пишет режим под итогом: `Режим: embedded (своя модель —
логика и кольца в её коде; …)`.

## Только формальный промпт

Своя модель не говорит на естественном языке ни в одном канале. Это
держится на двух уровнях:

1. **Генерация.** Декодер не выпускает утверждения вне ℒ: в ответе модели
   его нет физически.
2. **Граница ochan.** Даже если адаптер ошибётся или модель подключат в
   обход декодера, ochan не примет от роли `llm` в `embedded` текста не на
   языке:
   - письмо (`ochan mail send`) — только формальный промпт, что бы ни стояло
     в `mail.lang`;
   - записи инцидента (что случилось, заметка, решение, причина эскалации) —
     только формальный промпт.

```
$ ochan incident open --level critical --host db7 "PostgreSQL на db7 не принимает новые соединения"   # роль llm
ошибка: запись инцидента не на языке: что случилось — своя модель (llm.mode: embedded) пишет только формальным промптом
  1:1: ⊥syn: такой последовательности нет в языке; раздел начинается с одного из: goal:, classes:, relations:, priority:, generalization, instance, requires:, import, hard forbid|require, ??n_|??a_, cell, report:
  1:1: ⊥syn: программа начинается с заголовка goal: слово
  1:12: ⊥syn: символ «н» вне ASCII: язык — замкнутое подмножество английского, модель пишет только его

$ ochan incident open --level critical --host db7 "$(cat summary.fp)"
Инцидент 1be70bc3cb (critical) открыт: модель чинит сама до 09:09 (15m)
```

Текст модели проверяется строже текста оператора: кроме ⊥syn, в нём нет
комментариев (комментарий — естественный язык) и символов вне ASCII. Тексты
мониторинга (вебхук `POST /v1/incidents`) — внешние данные, и они остаются
как есть.

### Имена и строки

Язык ℒ закрыт по словам, но имена частных случаев в нём открыты (`o_17`,
`prod_conf`): их смысл задаёт место в структуре. В тексте оператора так и
должно быть. Модель же через открытое имя сказала бы что угодно —
`please_restart` тоже имя. Поэтому в тексте своей модели — в ответе, письме,
записи инцидента, отчёте сценария — имя допустимо, только если его можно
проверить:

- оно есть в задаче, на которую модель отвечает;
- его знает ochan: хост инвентаря, агент, заявка `request_<номер>`,
  инцидент `incident_<номер>`;
- оно составлено из слов словаря W через `_` (служебные и ключевые слова,
  единицы и числа — тоже части): `connection_limit`, `database_quota`;
- это новая ячейка `cK` — так модель называет ячейку своих решений.

Задача ответа — та, что модель получила: `--prompt` у `llm generate` и
`llm run`, инцидент у его записей, письмо `--reply` и файл `--prompt` у
`mail send`. Цикл агента отвечает на письмо с `--reply`, поэтому имена
письма модели доступны. Без задачи — только объекты ochan и слова языка:

```
$ ochan mail send --to db7 task.fp                    # роль llm, агент db8
ошибка: письмо не на языке: агентам пишут только формальным промптом
  13:13: ⊥syn: имя «max_connections» не из задачи и не из словаря объектов ochan, а слов языка в нём нет: модель имён не придумывает — открытым именем она говорила бы мимо языка

$ ochan mail send --to db7 --prompt task.fp task.fp
Письмо e87f2a9994 (формальный промпт)
  в ящики: db7
```

Строки `binds_to:` и `import` модель пишет только так, как они стоят в
задаче: путь и версию она не выбирает.

**Сценарий своей модели** (`plan` и `request` от роли `llm`) —
тоже формальный язык, но его комментарии и строковые литералы
(`print("…")`) — канал для естественного языка. Поэтому в сценарии своей
модели комментариев нет, а строка — только имя из задачи или объекта
ochan, путь из `binds_to:` задачи или значение с единицей (`"300"`,
`"8MB"`):

```
$ OCTOCHAN_ROLE=llm ochan plan note.ochan
ошибка: своя модель (llm.mode: embedded) пишет только на ℒ — в сценарии и отчёте нет естественного языка:
  note.ochan:1:7: строка "Please restart the database now" в сценарии своей модели: в строке — только имя, путь или значение из задачи и объектов ochan; текст в ней был бы естественным языком
  note.ochan:2:11: строка "max_connections" в сценарии своей модели: в строке — только имя, путь или значение из задачи и объектов ochan; текст в ней был бы естественным языком

$ OCTOCHAN_ROLE=llm ochan plan bad.ochan --prompt bound.fp     # binds_to: prod.conf:1-1
ошибка: своя модель (llm.mode: embedded) пишет только на ℒ — в сценарии и отчёте нет естественного языка:
  bad.ochan:2:8: строка "please_restart" в сценарии своей модели: в строке — только имя, путь или значение из задачи и объектов ochan; текст в ней был бы естественным языком
```

С той же задачей сценарий `put(c, "max_connections", "300")` над
`"prod.conf"` проходит и строит план. Внешней модели (`protocol`) строки
нужны, и её сценарии так не проверяются.

## Права

| Действие | Право |
|---|---|
| `llm` — режим и движок | `read` |
| `llm generate` | `plan` |
| `llm run` — цикл агента; его действия идут от роли `llm` с её правами | `request` |
| `llm serve` — процесс адаптера на этой машине | `server` |

## Что сделано и что осталось

Своя модель ℒ работает целиком на своей машине: адаптер ставится
(`make install-llm`, `install.ps1 -Llm`) и держится ochan (`llm serve`,
autostart), её ответ становится действием (`llm run`), а граница ochan
закрыта по языку, именам и строкам сценариев. Python-часть проверяется
тестами: `make llm-test` (`cd llama && python -m unittest discover -s
tests`), корпус — `make fpcheck`.

Остаётся то, что делает не код, а обучение и эксплуатация:

- **Веса.** В репозитории их нет: модель обучают на своей машине
  (`llama/train_own.py`, на видеокарте или `--device cpu`), затем её
  параметры уточняют журнал решений (`fit.py`) и инциденты (`learn.py`).
- **Сценарии реализации.** Переход от решения к изменению системы пишет
  оператор (`${Класс.атрибут}`); чем больше типовых сценариев, тем больше
  инцидентов модель закрывает без человека.
- **Словарь объектов.** Имена параметров, которых нет в W (`max_connections`),
  модель пишет только из задачи. Словарь параметров по видам конфигов
  открыл бы их и без задачи.
