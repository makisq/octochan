# Язык алиасов

Небольшой язык сценариев ochan: 24 ключевых слова, 86 встроенных функций,
строгие типы, записи и интерфейсы, функции и морфизмы конфигураций как
значения. Ключевые слова — латиницей, имена — на любом языке.

```
alias синхронизировать(эталон: config, цель: config, адреса: map) {
    if diff(эталон, цель) != 0 {
        print("расходятся:", diff_list(эталон, цель))
        for сервер: string in адреса {
            применить(цель, сервер, адреса[сервер])
        }
        return len(адреса)
    }
    return 0
}
```

## Запуск

```
ochan run сценарий.ochan                 выполнить файл
ochan run синхронизировать a.conf b.conf  вызвать алиас из библиотеки
ochan eval "diff('a.conf', 'b.conf')"    вычислить выражение
ochan check сценарий.ochan               проверить, ничего не выполняя
ochan check                              проверить всю библиотеку алиасов
ochan plan сценарий.ochan                что сценарий изменил бы
ochan request сценарий.ochan             заявка на выполнение
ochan aliases                            алиасы библиотеки и встроенные функции
```

`run` выполняет файл, если первый аргумент — существующий файл или `-`;
иначе это имя алиаса, а остальные аргументы — его параметры (числа
распознаются, остальное — строки). Изменения, которые сценарий может
сделать, лучше проводить через [план и заявку](requests.md): `run` пишет
сразу.

Алиасы библиотеки лежат в `~/.octochan/aliases/*.ochan` и в пакетах
`~/.octochan/modules` (см. [«Модули и пакеты»](modules.md)).

## Лексика

- Комментарий — от `#` до конца строки. Комментарии прямо над `alias` —
  его описание: его показывает `ochan aliases`.
- Инструкции разделяются переводом строки или `;`. Внутри `( )` и `[ ]`
  перевод строки незначим, поэтому длинные списки аргументов переносятся
  свободно; в остальных местах строку продолжает `\` в её конце. Внутри
  `{ }` перевод строки снова значим, даже если скобки стоят в аргументах:
  тело функции, переданной аргументом, пишется по строкам.
- Строки — в двойных или одинарных кавычках (одинарные удобны, когда
  двойные съедает оболочка, например PowerShell). Escape: `\n`, `\t`,
  `\r`, `\\`, `\'`, `\"`; неизвестная последовательность — ошибка.
- Числа: `42`, `1_000_000`, `2.5`. `8GB` — не число, а ошибка разбора:
  размер пишется строкой `"8GB"`, и сравнение конфигов поймёт его по смыслу.
- Имена — буквы любого алфавита, цифры и `_`: `лимит`, `server_1`.
- Ключевые слова: `alias var let fn record interface trait import if
  else for in parallel try catch return break continue and or not true
  false null`.

## Типы и значения

| Тип | Также пишется | Литерал или откуда берётся |
|---|---|---|
| `int` | `целое` | `42` |
| `float` | `дробное` | `2.5` |
| `number` | `число` | целое или дробное |
| `string` | `строка` | `"текст"`, `'текст'` |
| `bool` | `логическое` | `true`, `false` |
| `list` | `список` | `[1, 2, 3]` |
| `map` | `словарь`, `dict` | `{"db1": "10.0.0.11"}` |
| `config` | `конфиг` | `config("prod.conf")` |
| `stream` | `поток` | `stdout()`, `stderr()`, `file("отчёт.txt")` |
| `fn` | `функция` | `fn(x) => x * 2`, `fn len` |
| `morph` | `морфизм` | `a -> b`, `morph({"x": "1"})` |
| `functor` | `функтор` | `functor({"a": "b"})` |
| имя записи | | `Сервер("db1")` |
| имя интерфейса | | любое подходящее значение |
| `any` | `любой` | значение любого типа |

`null` — отсутствие значения. Ложны `false`, `0`, `""`, `null`, пустые
список и словарь и конфиг без параметров; остальное истинно.

Неудачная операция — ошибка, прерывающая сценарий, а не число: `diff`
возвращает количество расхождений, и условие пишется `diff(a, b) != 0`.

## Переменные

Переменная строго типизирована: тип задаёт объявление, а без аннотации —
первое значение, и дальше он не меняется.

```
var порт: int = 5432        # тип написан
var имя = "prod"            # тип — строка, по значению
var счётчик: int            # нулевое значение: 0
лимит: int = 200            # то же, что var лимит: int = 200
x = 1                       # необъявленная переменная объявляется: целое
x = "a"                     # ошибка: тип целое задан первым значением
```

```
ошибка: переменная x: тип целое задан первым значением, присваивается значение типа строка (a):
тип переменной не меняется; для таких значений объявите её как var x: any
```

- Целое там, где объявлено дробное или число, — расширение без потери
  данных: `var x: number = 1`, затем `x = 2.5`. Для значений любого типа —
  `var x: any`. Подсказка в ошибке называет, какой тип объявить.
- Нулевые значения: `0`, `0.0`, `""`, `false`, `[]`, `{}`, `null` для
  `any`. У конфига и потока нулевого значения нет — их объявляют со
  значением.
- Строка числом не считается: `var порт: int = "5432"` — ошибка.
- Блок `{ … }` — своя область: переменная, заведённая внутри `if`, после
  него не видна. Повторное объявление в той же области — ошибка, во
  вложенной — новая переменная, которая затеняет внешнюю.
- Присваивание без `var` пишет туда, где переменная уже объявлена, —
  в том числе во внешнюю область.

## Операторы

От слабого к сильному:

| Приоритет | Операторы |
|---|---|
| 1 | `or` |
| 2 | `and` |
| 3 | `not` |
| 4 | `==` `!=` `<` `<=` `>` `>=` |
| 5 | `\|` — конвейер |
| 6 | `>>` — композиция функций, морфизмов, функторов |
| 7 | `->` — морфизм между конфигами |
| 8 | `+` `-` |
| 9 | `*` `/` `%` |
| 10 | унарный `-` |
| 11 | вызов `f(…)`, индекс `x[…]`, поле `x.поле`, метод `x.f(…)` |

- `and` и `or` вычисляют правую часть, только если она нужна.
- `+` складывает числа, склеивает строки (`"a" + 1` — `"a1"`) и списки.
  Строка, похожая на число, в остальной арифметике — число: `"5" - 1` — 4.
  Два целых дают целое, целое с дробным — дробное; `/` всегда дробное.
- Сравнение чисел — численное, остального — по тексту.
- Конвейер: `a | f(b)` — это `f(a, b)`; левое значение — первый аргумент и
  сохраняет свой тип: `lines(текст) | len`. Он связывает крепче сравнения,
  поэтому `a | b != 0` — это `(a | b) != 0`.

## Управление

```
if n > 10 {
    print("много")
} else if n > 0 {
    print("есть")
} else {
    print("пусто")
}

for сервер in ["db1", "db2"] { print(сервер) }
for n: int in [1, 2, 3] { print(n) }      # тип элемента проверяется
for i in [1, 2, 3, 4] {
    if i == 2 { continue }
    if i == 4 { break }
    print(i)
}
```

`for` обходит список по элементам, словарь и конфиг — по ключам в
алфавитном порядке, строку — по строкам. Остановить сценарий с ошибкой —
`fail("сообщение", значение)`; код возврата `ochan run` — 1.

## Алиасы

```
# задать параметр конфига
alias set_param(c: config, name: string, value: string) {
    put(c, name, value)
    return c
}
```

- Типы параметров необязательны. Написанный тип проверяется при вызове —
  ошибка всплывает на входе в алиас, а не в его середине; ненаписанный
  задаёт переданное значение.
- `return` без значения и конец тела возвращают `null`. Алиас без
  параметров можно вызвать без скобок: `версия` — то же, что `версия()`.
- Алиас не видит переменных вызывающего — только свои параметры.
- Алиас можно вызвать до его объявления в файле. Рекурсия ограничена
  глубиной 1000: `alias a() { a() }` не повесит процесс.
- Алиас пакета вызывается как `пакет.алиас(…)`; короткое имя работает,
  пока оно не занято в нескольких пакетах.
- Алиас с именем встроенной функции её перекрывает.

## Функции

Функция — значение, как число или список: её кладут в переменную,
передают аргументом, возвращают из алиаса и вызывают.

```
double = fn(x) => x * 2                       # тело-выражение
add = fn(a: int, b: int): int {               # тело-блок, типы
    return a + b
}
print(double(21), add(2, 3))                  # 42 5

проверить = fn проверить_сервер               # алиас как значение
длина = fn len                                # встроенная функция

alias сумматор(n) { return fn(x) => x + n }   # функция из алиаса
print(сумматор(10)(5))                        # 15
```

- `fn(…) => выражение` — короткая функция, `fn(…) { … }` — с телом
  и `return`. Типы параметров и результата (`fn(x: int): int`) проверяются
  при вызове, как у алиаса. Тип функции — `fn` (`функция`).
- Голое имя алиаса без скобок — вызов, поэтому алиас и встроенная функция
  как значения пишутся через `fn`: `fn len`, `fn devops.проверить`.
- Функция видит переменные снаружи такими, какими они были в момент её
  создания, — снимок. Присвоить им функция не может: внутри функции
  объявляют свои. Словарь в снимке — тот же словарь: `put` его меняет.
- Функция, которую сразу присваивают переменной, видит себя под этим
  именем, и так работает рекурсия:

```
let fact = fn(n: int): int {
    if n <= 1 { return 1 }
    return n * fact(n - 1)
}
```

Функции высшего порядка:

| Функция | Что делает |
|---|---|
| `each(список, f)` | результаты `f` для каждого элемента |
| `filter(список, f)` | элементы, для которых `f` истинна |
| `reduce(список, f, начало)` | свёртка: `f(итог, элемент)` |
| `sort(список[, ключ])` | сортировка, устойчивая; `ключ` — функция |
| `call(f, …)` | вызвать `f` с аргументами |
| `partial(f, …)` | закрепить первые аргументы |
| `compose(f, g, …)` | то же, что `f >> g >> …` |
| `id()` | тождественная функция |
| `range(n)`, `range(a, b[, шаг])` | список целых |

Как и `for`, они обходят словарь и конфиг по ключам, строку — по строкам.

```
живые = filter(серверы, fn(s) => s != "db3")
адреса = each(живые, fn(s) => s + ".internal")
всего = reduce(each(конфиги, fn params), fn(n, x) => n + x, 0)
по_размеру = sort(файлы, fn(f) => len(read(f)))
```

**Композиция** `f >> g` — функция, которая применяет `f`, а к её
результату `g`. Операнды — функции, поэтому голое имя алиаса здесь — сам
алиас, а не его вызов:

```
нормализовать = trim >> lower >> fn(s) => s + ".conf"
print("  Prod " | нормализовать)              # prod.conf
```

Справа от конвейера можно поставить любую функцию: `x | f`, `x | f >> g`,
`x | fn(v) => v * 2`.

**`let`** объявляет переменную, которой нельзя присвоить новое значение:
`let порог = 200`. Во вложенной области её можно затенить своей
переменной.

## Записи и интерфейсы

**Запись** — именованный набор полей с типами:

```
# сервер базы
record Сервер {
    имя: string
    порт: int = 5432
    теги: list = []
}

db1 = Сервер("db1")                           # по порядку полей
db2 = Сервер(имя: "db2", порт: 6432)          # по именам
db1.порт = 5433
db1.теги = ["prod"]
print(db1)                                    # Сервер(имя: "db1", порт: 5433, теги: [prod])
print(to_json(db1))                           # {"имя":"db1","порт":5433,"теги":["prod"]}
```

- Поле без значения по умолчанию обязательно; тип поля проверяется и при
  создании, и при каждой записи:

```
ошибка: сервер.ochan:22:9: поле порт записи Сервер: объявлен тип целое, получено значение типа строка (5433)
```

- Имя записи — тип: `alias адрес(s: Сервер)`, `var основной: Сервер = db1`.
  Запись из пакета — `devops.Узел`.
- Запись передаётся как словарь: алиас, изменивший поле, изменил его и у
  вызывающего. `let` запрещает новое значение переменной, а не правку
  полей.
- `==` сравнивает записи по полям, `to_json` и `to_yaml` превращают их в
  объекты.

**Вызов через точку.** `x.f(a)` — то же, что `f(x, a)`: так алиас
становится методом, а цепочки встроенных функций читаются слева
направо. Если у записи или словаря есть поле-функция с этим именем,
вызывается она.

```
alias адрес(s: Сервер) { return s.имя + ":" + str(s.порт) }
print(db1.адрес())                            # db1:5433
print("  Prod ".trim().lower())               # prod
```

**Интерфейс** — поля и методы, которые нужны от значения. Объявлять, что
запись его реализует, не нужно: подходит любое значение с такими полями,
для которого есть такие методы — алиасы, встроенные функции или
поля-функции.

```
interface Адресуемый {
    имя: string
    адрес()
}

# метод по умолчанию: работает для всего, что подходит под интерфейс
alias описание(x: Адресуемый) { return "узел " + x.адрес() }
print(db2.описание())                         # узел db2:6432
```

`trait` — то же, что `interface`: методы по умолчанию — алиасы, первый
параметр которых объявлен интерфейсом. Проверка до запуска сверяет
записи с интерфейсами; при выполнении неподходящее значение — ошибка с
объяснением:

```
ошибка: сервер.ochan:21:9: параметр x алиаса описание: значение типа словарь ({"имя": x}) не подходит под интерфейс Адресуемый: нет метода адрес(): ни поля-функции, ни алиаса или встроенной функции адрес, которая принимает это значение единственным аргументом
  в алиасе описание
```

`type_of(x)` — имя типа (`int`, `string`, `Сервер`…), `is(x, "Адресуемый")` —
подходит ли значение под тип.

**Присваивание полю и элементу:** `m.ключ = v` и `m["ключ"] = v` для
словаря, `c["max_connections"] = "200"` для конфига, `список[0] = v`.

**Именованные аргументы** — у алиасов, функций и записей:
`вычесть(b: 1, a: 10)`, `Сервер("db1", порт: 6432)`. Сначала аргументы по
порядку, потом по именам; встроенные функции принимают только по
порядку.

## Пакеты и import

Пакеты из `~/.octochan/modules` подключены всегда. `import` делает
зависимость сценария явной: проверяет до запуска, что пакет есть и
подходит по версии, и может дать ему короткое имя:

```
import devops v2 as d
u = d.Узел("db1")
print(d.проверить(u), u.проверить())
```

- Версия: `v2` — любая 2.x.y, `v2.1` — 2.1.x, `v2.1.3` — ровно она.
  Неподходящая — ошибка до выполнения:

```
ошибка: деплой.ochan:1:1: import devops v3: подключена версия 2.1.0
```

- `as` — второе имя пакета, только в этом сценарии.
- `import` пишут в сценарии; в файле библиотеки он ошибка — второе имя
  стало бы видно всем.
- Заявка запоминает версии пакетов и файлы библиотеки, от которых зависит
  сценарий, — алиасов, записей и интерфейсов.
- Переменная перекрывает пакет с тем же именем: если есть переменная `d`,
  `d.проверить` — её поле.

## Морфизмы и функторы

Для сложных оркестраций. Обычная правка говорит «поставь
`max_connections = 200`». Морфизм говорит «из такой конфигурации — в
такую»: он помнит, что меняется и с какого значения, и прежнее значение —
условие его применения. Отношение между конфигурациями становится
значением: его хранят в переменной, печатают, композируют и проверяют до
того, как что-то записано.

```
let перевод = config("test.conf") -> config("test-new.conf")
print(перевод)
print(dom(перевод))                           # условия
print(cod(перевод))                           # результат
save(перевод(config("prod.conf")), "prod.conf")
```

```
морфизм test.conf -> test-new.conf: max_connections 100 -> 200; new_param добавить = on; old_param удалить
{"max_connections": 100, "new_param": null, "old_param": 1}
{"max_connections": 200, "new_param": on, "old_param": null}

План: перевод.ochan -> —

Изменений: 3

  prod.conf
    изменить   max_connections: 100 -> 200
    удалить    old_param (было 1)
    добавить   new_param = on
```

- `a -> b` — морфизм из конфига `a` в конфиг `b`; операнды — конфиги,
  словари (`{"секция": {"ключ": значение}}`) или источники, как у
  `config`.
- `m(c)` применяет морфизм и возвращает новый конфиг, `c` не меняется.
  Применяется не только к `a`, а к любому конфигу с теми же исходными
  значениями меняющихся параметров; остальные параметры не трогаются
  (`work_mem` прода выше остался своим). Несовпадение — ошибка, а не
  тихая перезапись чужой правки:

```
ошибка: перевод.ochan:2:8: морфизм test.conf -> test-new.conf не применяется к конфигу prod2.conf: ожидается max_connections = 100, в конфиге 150
```

- Морфизм между словарями описывает ровно меняемые параметры:
  `{"shared_buffers": "1GB"} -> {"shared_buffers": "4GB"}`. Морфизм от
  всего конфига к желаемому требует только то, что меняет, а меняет всё,
  чем они различаются, — и чужую правку, сделанную после согласования,
  тоже. Для выкатки описывайте морфизм по своим параметрам — пример в
  [кукбуке](../cookbook/morphisms.md).
- `morph({"параметр": значение})` — задать значение, что бы ни стояло
  (`null` — удалить); `morph(fn(c) => …)` — морфизм-функция конфиг →
  конфиг.
- `m1 >> m2` — сначала `m1`, потом `m2`. Дельты склеиваются сразу, и то,
  что после первого не совпадает с условием второго, — ошибка до всякой
  записи:

```
print(перевод >> morph({"max_connections": "300"}))
# морфизм: max_connections 100 -> 300; new_param добавить = on; old_param удалить
print(перевод >> перевод)
# ошибка: морфизмы не стыкуются: после первого max_connections = 200, второй ожидает 100
```

- `inverse(m)` — обратный морфизм `b -> a`; `id()` — тождественный, он
  нейтрален в `>>`. Значения сравниваются по смыслу, как в `diff`:
  `8GB` и `8192MB` равны.

**Коммутативность.** `commutes(p, q)` — дают ли два пути одно и то же;
`conflicts(p, q)` — чем они расходятся (пустой список — коммутируют).
Дельты сравниваются без конфигов, на всём их общем начале; морфизмы-функции
так не сравнить, и им передают объекты проверки: `commutes(p, q,
[конфиги])`.

Две команды правят один конфиг — зависит ли итог от порядка:

```
команда_а = morph({"work_mem": "64MB"})
команда_б = morph({"shared_buffers": "4GB"})
print(commutes(команда_а >> команда_б, команда_б >> команда_а))     # true

команда_в = morph({"work_mem": "32MB"})
print(conflicts(команда_а >> команда_в, команда_в >> команда_а))
# [work_mem: по первому пути 32MB, по второму 64MB]
```

Коммутативный квадрат оркестрации — синхронизировать стенд с боем и
мигрировать, или наоборот:

```
синхронизация = config("test.conf") -> config("prod.conf")
миграция = morph({"max_connections": "500"})
if not commutes(синхронизация >> миграция, миграция >> синхронизация) {
    fail("порядок важен:", conflicts(синхронизация >> миграция, миграция >> синхронизация))
}
```

**Функторы** переводят конфиги в конфиги и морфизмы в морфизмы, сохраняя
тождество и композицию, — соответствие на уровне машин и протоколов: та же
правка для PostgreSQL и для пула соединений перед ним, для стенда и для
боя.

```
к_пулу = functor({"max_connections": "pgbouncer.default_pool_size", "*": null})
print(к_пулу(перевод))
# морфизм test.conf -> test-new.conf: pgbouncer.default_pool_size 100 -> 200
save(к_пулу(перевод)(config("pgbouncer.ini")), "pgbouncer.ini")
print(functor_laws(к_пулу, [перевод], [config("test.conf"), config("prod.conf")]))   # []
```

- `functor({"старое": "новое"})` — переименование параметров; `null` —
  забыть параметр, `"*": null` — забыть все неперечисленные. Такой
  функтор переводит и конфиги, и дельты.
- `functor(fn(c) => …[, fn(m) => …])` — функция над конфигами и, если
  нужно, над морфизмами. Без второй функции образ морфизма строится по
  объекту: `F(m, c)` — стрелка `F(c) -> F(m(c))`.
- `F(c)`, `F(m)`, `F >> G`. `functor_laws(F, [морфизмы], [конфиги])`
  проверяет на данных `F(id) = id` и `F(f >> g) = F(f) >> F(g)` и
  перечисляет нарушения.

## Конфиги, словари и списки

**Конфиг** разбирается один раз и живёт в переменной:

```
цель = config("test.conf")                   # файл, текст или postgres://…
print(цель["max_connections"], цель["server.port"])
put(цель, "max_connections", "200")
save(цель, "patched.conf")
```

Короткое имя параметра ищется среди параметров без секции, затем по всем
секциям; совпадение в нескольких — ошибка с требованием уточнить секцию.
`config(источник, "all")` для живого источника берёт и параметры со
значениями по умолчанию.

**Словарь** — карта «ключ → значение»:

```
адреса = {"srv1": "10.0.0.11", "srv2": "10.0.0.12"}
for сервер in адреса { print(сервер, адреса[сервер]) }
put(адреса, "srv3", "10.0.0.13")
print(keys(адреса), has(адреса, "srv1"), get(адреса, "srv9", "нет"))
```

Фигурные скобки в начале инструкции открывают блок, поэтому литерал
словаря пишется там, где ожидается выражение: `x = {"k": 1}`.

`get`, `put`, `has`, `keys`, `values`, `merge` работают и со словарями, и
с конфигами.

## Файлы и вывод

```
текст = read("prod.conf")                    # прочитать файл
if exists("report.txt") { … }
write("report.txt", "готово\n")              # записать целиком
save(config("x = 1\n"), "new.conf")          # записать конфиг
```

`print` печатает значения через пробел и переводит строку. Первым
аргументом можно передать поток — тогда строка идёт в него:

```
отчёт = file("отчёт.txt")   # поток в файл: print дописывает строку
print(отчёт, "сервер", имя, "готов")
print(stderr(), "не удалось:", ошибка)
print("на экран")           # то же, что print(stdout(), "на экран")
```

`write`, `save` и печать в файл — **записи**: в режиме плана они ничего
не пишут, но попадают в план; песочница проверяет путь (для потока — уже
в `file()`); жёсткое правило промпта о `write` касается и печати в файл;
выполненный по заявке сценарий откатывает все три. Печать подряд в один
файл — одно изменение плана. `save` пишет файл целиком: комментарии и
порядок строк не сохраняются, и план об этом предупреждает.

## Строки, числа и время

`format` собирает строку по образцу, как `printf`:

```
print(format("id=%d, имя=%s", n, имя))       # id=7, имя=prod
print(format("%.2f%%", доля * 100))          # 12.50%
print(format("%-10s|%5d|", "ab", 7))         # ab        |    7|
```

Глаголы — `%d %f %s %v %q %x %t %%`, с шириной и точностью. Глагол, не
подходящий к значению (`%d` для строки), недостающий или лишний аргумент —
ошибка, а не `%!d(string=…)` в выводе.

Строки: `upper`, `lower`, `trim(s[, символы])`, `split(s, разделитель)`,
`replace(s, старое, новое)`, `contains` (подстрока или элемент списка),
`starts_with`, `ends_with`, а также `join`, `lines`, `len`.

Математика: `sqrt`, `pow`, `abs`, `floor`, `ceil`, `round(x[, знаков])`,
`min` и `max` — от нескольких аргументов или от списка, `float`.

Случайность: `rand()` — дробное от 0 до 1, `rand(n)` — целое от 0 до n-1,
`rand(a, b)` — от a до b, `choice(список)`, `shuffle(список)`.

Время: `now()` (или `time.now()`) — время запуска сценария в RFC 3339,
`time.format("%Y-%m-%d %H:%M", t)`, `time.add(t, "1h30m")`,
`time.unix(t)`, `sleep(2)` и `time.sleep("500ms")`.

`now()` возвращает не текущее время, а время запуска: сценарий видит одно
время от начала до конца. Заявка запоминает его и зерно `rand` вместе с
планом, и при выполнении `now()` и `rand()` возвращают то же, что в плане, —
иначе выполнилось бы не то, что согласовали. Карточка заявки их
показывает:

```
Время:     2026-10-23T13:33:04.512+03:00, зерно rand 4105861375926143281
```

В режиме плана `sleep` не ждёт. В `parallel for` у каждой итерации своя
последовательность случайных чисел, выведенная из зерна и номера
элемента: порядок итераций на неё не влияет.

## Данные и сеть

```
данные = from_json(read("servers.json"))
print(данные["prod"]["port"])
write("servers.yaml", to_yaml(данные))
print(to_json(данные, true))                 # с отступами
настройки = from_toml(read("app.toml"))
```

`to_json`/`from_json`, `to_yaml`/`from_yaml`, `to_toml`/`from_toml`
переводят между текстом и словарями, списками, числами и строками.
Числа JSON остаются целыми, если они целые.

`eval("2 + 3 * 4")` вычисляет одно выражение из строки. Выражение
проверяется перед вычислением той же проверкой, что и сценарий, и
выполняется с той же песочницей и в том же режиме плана: объявления и
инструкции в нём не принимаются.

`fetch(url)` возвращает тело ответа на GET, `curl(url)` — ответ целиком:

```
статус = from_json(fetch("https://status.example.com/api/v1/db"))
ответ = curl("https://status.example.com/health", {"method": "HEAD", "timeout": "5s"})
print(ответ["status"], ответ["headers"]["content-type"])
```

Сценарий только читает: методы — `GET` и `HEAD`. Изменить внешнюю систему —
дело исполнителя и заявки. Ответ — до 10 МиБ, ожидание — до 5 минут, код
4xx и 5xx для `fetch` — ошибка, `curl` его возвращает. Каждое обращение
видно в плане, как обращение к живому источнику:

```
План: статус.ochan -> —
внимание: сценарий читает живой источник GET https://status.example.com/api/v1/db
```

В песочнице без `--allow-net` сеть закрыта:

```
ошибка: статус.ochan:1:20: сеть в песочнице закрыта: status.example.com не разрешён (--allow-net status.example.com)
```

План ходит в сеть по-настоящему: если ответ к выполнению изменится,
изменится и план, и заявку не выполнят.

## Ошибки и параллельность

Основной сценарий предметной области — «раскатать на полсотни серверов,
продолжить при отказе двух и отчитаться»:

```
parallel for сервер in сервера {
    try {
        применить(конфиг, сервер)
        print(сервер, "применено")
    } catch ошибка {
        print(сервер, "ПРОПУЩЕН:", ошибка)
    }
}
```

- **Вывод детерминирован.** Итерации идут одновременно, но вывод — на
  экран, в stderr и в файлы — ложится в порядке элементов, а не
  завершения. Поэтому план совпадает с выполнением, а прогоны сравнимы.
- **Одновременных итераций** не больше `defaults.max_parallel_tasks`
  (5): полсотни серверов не превращаются в полсотни подключений сразу.
- **Тело изолировано.** Оно видит копию внешних переменных, и его
  присваивания наружу не выходят:

  ```
  счётчик = 0
  parallel for n in [1, 2, 3] { счётчик = счётчик + n }
  print(счётчик)          # 0
  ```

  Без копии две итерации писали бы в одну переменную одновременно.
  Результат накапливается выводом — например, в файл.
- `break`, `continue` и `return` внутри `parallel for` запрещены: итерации
  уже идут, прерывать нечего.
- Неперехваченные отказы собираются в одну ошибку со списком целей:

  ```
  parallel for: неудачных итераций 2 из 4:
    srv2: недоступен
    srv4: отказ применения
  ```

`catch` ловит только ошибки; `break`, `continue` и `return` проходят сквозь
него — это управление, а не сбой. Имя после `catch` необязательно; в нём
текст ошибки (строка).

## Проверка до запуска

Интерпретатор находит ошибку, только когда до неё дошло выполнение.
`ochan check` обходит все ветки и все алиасы и ничего не выполняет:

```
сценарий.ochan:4:38: неизвестная функция "diff_lst"; возможно, имелось в виду "diff_list"
сценарий.ochan:5:9: break допустим только внутри for
сценарий.ochan:9:1: переменная x: тип целое задан первым значением, присваивается значение типа строка: …
сценарий.ochan:14:7: неизвестное имя "y"
```

Находится всё, что видно без запуска: неизвестные имена и функции,
переменные вне своей области, число аргументов, `break`, `continue` и
`return` не на своём месте, повторное объявление, явно неверные типы,
деление на ноль. Все ошибки сразу. Ложная тревога хуже пропуска, поэтому
отвергается только то, что неверно наверняка; остальное проверит
интерпретатор. `plan` и `request` проверяют сценарий так же перед планом.

## План сценария

```
$ ochan plan rollout.ochan
готово, отчёт — rollout.log

План: rollout.ochan -> —

Изменений: 10

  /srv/configs/out/db1.conf
    добавить   max_connections = 200
    добавить   shared_buffers = 4GB
    добавить   work_mem = 16MB
  …
  /srv/configs/rollout.log
    записать   файл — новый файл, 114 байт
```

Сценарий выполняется в режиме плана: записи только запоминаются, а
дальше по сценарию записанное видно — `read` того же файла вернёт новое
содержимое, иначе план описывал бы не тот сценарий. Чтение файлов и
живых источников настоящее; обращение к живому серверу план называет
отдельно. `save` раскладывается по параметрам — с удалениями, в отличие
от `patch`. Порядок изменений — порядок выполнения.

## Песочница

Без флагов сценарий умеет всё, что умеет запустивший его человек. Для
сценария, который написал не человек:

```
ochan plan --sandbox --root ./configs --allow-env APP_ENV --allow-live postgres \
  --allow-net status.example.com сценарий.ochan
ochan run  --sandbox --root ./configs сценарий.ochan
```

- файлы — только внутри `--root` (по умолчанию — текущий каталог);
  символические ссылки раскрываются до проверки, висячие отвергаются;
- переменные окружения — только из `--allow-env`: среди них токен API и
  пароли;
- живые источники — только схем из `--allow-live`;
- `fetch` и `curl` — только к хостам из `--allow-net` (`хост` или
  `хост:порт`), в том числе после перенаправления; по умолчанию сеть
  закрыта.

Отказ — ошибка с объяснением, а не пустое значение. Сервер MCP запускает
сценарии нейросети всегда в песочнице.

Проверки языка — первая стена. Вторую держит ядро: сценарий в песочнице
выполняется отдельным процессом ochan, и на Linux Landlock не пустит его к
файлам вне `--root`, seccomp — к запуску программ, отладке чужих процессов,
монтированию и сокетам, а своё сетевое пространство оставит без сети.
`ochan sandbox` показывает, что из этого есть на машине; на macOS и Windows
файлы и сеть держит только язык, и ochan об этом предупреждает. С
`sandbox.strict: true` неполная песочница — отказ. План и выполнение идут
одним путём, поэтому заявка, построенная в песочнице, выполняется и
откатывается как обычно.

Рабочий каталог ochan (`~/.octochan`) закрыт для встроенных функций
всегда — в песочнице и без неё: там роли, ключ подписи допусков сервера и
токены. Роль с [областью](roles.md#область) выполняет сценарии только в
песочнице — без `--sandbox` она ставится сама, с текущим каталогом.
Подробно — [«Безопасность»](security.md).
