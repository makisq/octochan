# Язык интерфейса

## Выбор языка

```yaml
# ~/.octochan/config.yaml
lang: eng      # ru (по умолчанию), eng или en; другие — из модулей
```

Язык действует с запуска ochan: поменяли `lang` — перезапустите ochan
(и оболочку тоже). `ochan lang` показывает текущий язык, встроенные и
пришедшие из модулей и сколько справки переведено:

```
* en   English      built-in             help translated: 159 of 159
  ru   Русский      built-in             help translated: 159 of 159
```

На английский переведены справка всех команд (описания, примеры, флаги),
оболочка, общие сообщения и вывод новых команд; остальные сообщения
переводятся постепенно, и чего нет в переводе, остаётся по-русски. Тесты
требуют перевод для каждого текста справки и каждого сообщения, которое
код переводит через `i18n`.

Протокол формального промпта и описания инструментов MCP — всегда
по-английски, при любом `lang`: их читает модель.

Неизвестный `lang` ochan не останавливает: он говорит по-русски и
предупреждает на русском и английском, какой модуль поставить:

```
внимание: lang: язык "jp" не найден; доступны: en, ru. Другой язык ставится модулем: ochan !!install <модуль>
warning: lang: language "jp" is not available (en, ru); install its module with ochan !!install <module>
```

## Другой язык — модулем

Немецкий, японский или китайский не требует пересборки ochan: язык
приносит модуль — такой же Go-плагин, как модуль команд, только вместо
команд (или вместе с ними) он отдаёт по gRPC словарь «русский текст →
перевод». Пример — [examples/langmodule](../../examples/langmodule):
немецкий, словарь в JSON.

```
ochan lang template de > de.json                 # шаблон: что переводить
# перевести значения в de.json, положить его в examples/langmodule
go build -o lang-de.hcplugin ./examples/langmodule
ochan '!!install' lang-de.hcplugin                # модуль ставится и остаётся
# в config.yaml: lang: de — и со следующего запуска ochan по-немецки
```

Шаблон — JSON-объект: ключ — русский текст справки или сообщения,
значение — перевод (пусто — ещё не переведено). Модуль отдаёт его через
`GetTranslations` (`pluginhost/command.proto`), реализуя интерфейс
`pluginhost.Translator`:

```go
func (language) Translations() []pluginhost.Language {
    return []pluginhost.Language{{Code: "de", Name: "Deutsch", Entries: entries}}
}
```

- Чего нет в словаре модуля, берётся из английского, а чего нет и там —
  остаётся по-русски.
- Встроенный английский модуль переписать не может: модуль с кодом `en`
  только дописывает то, чего в нём нет.
- Модуль может перевести и команды других модулей — их справка тоже идёт
  через словарь.
- Имя команды (первое слово строки вызова) не переводится никогда: по нему
  ochan находит команду.
- Модули, собранные до появления языков, на `GetTranslations` отвечают
  «не реализовано», и ochan считает, что языков у них нет.

## Что переживает перезапуск

| Что | Где |
|---|---|
| конфиг, в том числе `lang` | `config.yaml` |
| установленные модули команд и языков, пакеты алиасов | `modules/` (с контрольными суммами) |
| роли, права, текущая роль и история переключений | `roles.bin` |
| журнал операций и заявки | `history/`, `requests/` |
| история команд оболочки, выбор `--logo` / `--no-logo` | `state.json` |

Поэтому путь «поставил модуль — вышел — поменял `lang` — зашёл» работает
как ожидается: модуль на месте, язык другой, роль и история — прежние.

История оболочки: стрелка вверх и `!!history` после перезапуска показывают
и прежние команды. Пароли в ссылках (`postgres://dba:пароль@…`) и
`password=` в строках подключения записываются как `***`; строка, начатая
с пробела, не запоминается вовсе. Размер — `shell.history_size` (1000).
