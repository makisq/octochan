# Лама в ФПм-вид: контекст и задачи

Передача работы в новую сессию — ту, где есть доступ к ПК владельца. Прочитай
целиком перед первым шагом.

## Как работать с владельцем

- Отвечать по-русски, без эмодзи. Тексты для модели (протокол `fp/protocol*.md`,
  описания инструментов MCP) — по-английски.
- В документации — только настоящие выводы: команду запустить, вывод
  скопировать. Ничего не выдумывать: нет проверки — так и сказать.
- Git: рабочая ветка — та, что назовёт сессия. Никакого force-push: если PR
  ветки уже слит, ветку догнать до `main` (fast-forward или merge). PR открывать
  и сливать только по просьбе владельца. Идентификаторы моделей в коммиты и PR
  не писать.
- Токены и пароли в чат не просить: только через настройки окружения или
  переменные.

## Проект

octochan (`ochan`) — оркестратор для командной строки и CI с формальным
промптированием (ФПм). Репозиторий — `makisq/octochan` (бывший `makisq/PACAL`),
код в `octochan/`. Это модуль Go `octochan`, сервер MCP — отдельный модуль в
`octochan/mcp`. Версия — `0.3.0-alpha`. Манифест ФПм —
`octochan/docs/formal-prompting.md`, версия 0.4. Для задачи главное в нём:
раздел 6 (кольца 0–3 и встроенный режим), 9.2 (эксперимент), 10 (чего ФПм не
обещает) и 12 (уровни внедрения). Уровень 2 — «малая квантованная модель,
обученная на формальных промптах с обобщениями и частными случаями; здесь
кольца встраиваются в генерацию».

Сборка и проверки:

```
cd octochan
go build ./... && go vet ./... && gofmt -l .
go test ./...            # и в mcp/: cd mcp && go test ./...
go test ./cmd -run TestReference -update   # после смены справки команд
```

Под Windows: `powershell -ExecutionPolicy Bypass -File scripts\install.ps1`
(в `%LOCALAPPDATA%\Programs\ochan`, `-Bin` — другой каталог, `-Rlm` — с
модулем RLM) или `go build -o ochan.exe .`. На Windows нет песочницы ядра,
`--allow-exec` не работает, системная политика ролей — отказ.

## Что уже сделано

Слито в `main` (PR 17, 18, 19).

**Режимы модели.** `llm.mode: protocol | embedded | natural`; без него —
по прежнему `fp.mode`. `embedded` вместе с `fp.mode: natural` — отказ.
Код — `cmd/llm.go`.

**Пакет `embedded`** (`embedded/embedded.go`) — декодер встроенного режима:

- кольцо 0: токен с `p < llm.rings.tau` не берётся (по умолчанию τ = 0,42;
  на позицию проходит не больше ⌊1/τ⌋ = 2 токенов);
- маска языка на токене: `#` (комментарий), символ вне ASCII, табуляция,
  управляющие символы;
- утверждение — строка; готовая строка проверяется `fp.StatementSyntax`;
  не в языке — откат к началу строки, а токен, на который указала находка,
  запрещается на своём месте;
- позиция без токена выше порога — запрет предыдущего токена и откат; пусто
  в начале утверждения — ответа нет;
- конец ответа — проверка `fp.CheckModelText` целиком; не сложился — конец
  запрещён;
- выбор между кандидатами жадный и детерминированный; средний логарифм
  вероятности утверждения сохраняется (β₁ для `rings.Choose`).

**Протокол движка v1** (`embedded/http.go`) — контракт для адаптера Ламы:

```
GET  /v1/info  → {"protocol": 1, "engine": "llama.cpp", "model": "…"}
POST /v1/next  ← {"prompt": "…", "output": "…", "top": 2}
               → {"candidates": [{"text": "goal", "p": 0.81}, …], "end": 0.001}
```

- `prompt` — неизменная часть: протокол (`fp.ProtocolFor(fp.Formal)`), затем
  `\n\n# Task\n\n` и задача оператора. `output` — ответ до этого места.
- `p` — вероятность в **полном** распределении после softmax, **до** выборки:
  температура, top-p и штрафы не трогают. `end` — вероятность конца ответа
  (EOS / конец реплики). Кандидаты — по убыванию `p`; сумма с `end` ≤ 1,
  иначе ochan отказывает.
- `output` может кончаться не на границе токена: после `\n` ochan спрашивает
  заново с текста, кончающегося на `\n`. Адаптер токенизирует `prompt+output`
  сам.
- Сервер протокола вокруг любого `Engine` — `embedded.Handler`; пример —
  `examples/embeddedengine` (демонстрационный движок без знаний).

**Команды:** `ochan llm` (режим, движок), `ochan llm generate [--prompt
задача.fp] [--out файл]` (ответ — в stdout, сводка колец — в stderr, запись в
`~/.octochan/llm/generations.jsonl`). `ochan fp journal` начинается со сводки
колец (кольцо 0 — только в embedded), `ochan fp check` пишет режим.

**Язык модели.** Своя модель (роль `llm` при `llm.mode: embedded`) пишет
только формальным промптом: письма (`ochan mail send`) и записи инцидента
(что случилось, заметки, решение, причина эскалации). Текст модели строже
текста оператора: без комментариев и без символов вне ASCII
(`fp.CheckModelText`, `fp.ModelLexemes`).

**Почта** (`cmd/mail.go`). Агенты друг другу — только формальный промпт.
Людям — на языке режима (`mail.lang: auto | formal | natural`). Письма ochan
в формальном режиме — ячейками `set` (`cmd/mail_formal.go`).

Документация: `docs/guide/embedded.md`, `docs/guide/mail.md`,
`docs/cookbook/embedded-demo.md`.

Проверить цепочку без модели:

```
go build -o embedded-demo ./examples/embeddedengine
./embedded-demo --answer answer.fp --listen 127.0.0.1:8090 --chatter "0=Sure, here is what I found"
# config.yaml: llm: {mode: embedded, endpoint: http://127.0.0.1:8090}
ochan llm && ochan llm generate --prompt task.fp
```

## Задача: Лама в ФПм-вид, по порядку

Своя модель знает **только** формальный промпт и не должна уметь говорить на
естественном языке. Каждый шаг заканчивается замером против предыдущего; числа
— настоящие, из прогона.

**Шаг 0. Решения владельца и среда.**
- Модель. Предложено: Llama 3.2 1B Instruct (архитектурные правки и LoRA
  посильны без большой видеокарты), можно 3B. 8B в bf16 — около 16 ГБ: на
  слабой машине её можно только запускать в Q4. Выбор — за владельцем.
- Лицензия Meta на Hugging Face принимается его аккаунтом. Токен — через
  переменную `HF_TOKEN`, не в чат.
- Проверить машину: ОС, GPU (`nvidia-smi`), память, свободный диск (диск C
  забит — модели и кеши класть на другой диск: `HF_HOME`, `GOCACHE`,
  `GOMODCACHE`, кеш pip).
- Python-окружение: `torch` (CPU или CUDA по железу), `transformers`,
  `safetensors`, позже `peft`.

**Шаг 1. Базовая точка: модель и адаптер по протоколу v1.**
- Адаптер (Python, transformers): `GET /v1/info`, `POST /v1/next`. Для
  instruct-модели `prompt` оборачивается шаблоном чата (system — протокол,
  user — задача), `output` — начало ответа ассистента. `end` — вероятность
  EOS/конца реплики. Кеш KV по `prompt`.
- Проверка: `ochan llm` видит движок; `ochan llm generate --prompt task.fp`
  даёт ответ в ℒ или честный отказ.
- Замер на наборе задач: доля ответов в ℒ **без** маски (сырой вывод), с маской
  — откаты, утверждения вне ℒ, отклонённые кольцом 0, позиции без токена,
  время на ответ.

**Шаг 2. Словарь вывода = алфавит ℒ (первая правка архитектуры).**
- Собрать множество токенов, из которых складываются слова W (базовый
  `fp/lexicon.yaml`, словари скиллов и оператора), ключевые слова грамматики,
  типы отношений, служебные слова, единицы, коды отказов, цифры, знаки,
  пробелы и переводы строк, имена `[a-z][a-z0-9_]*`. Выгрузку алфавита ℒ из
  ochan, скорее всего, придётся добавить командой (например `ochan fp
  alphabet`).
- Обрезать выходной слой (`lm_head`) и эмбеддинги до этих токенов, с
  переотображением идентификаторов в токенизаторе. У Llama 3.2 1B словарь
  128 256 токенов, эмбеддинги связаны с выходом — около 260 млн параметров из
  1,2 млрд.
- Проверка: токена вне алфавита у модели нет (например, кириллицы); ответы
  шага 1 воспроизводятся; замер — как на шаге 1.

**Шаг 3. Дообучение (LoRA) на корпусе ℒ.**
- Корпус: формальные промпты, отчёты, обобщения и частные случаи; из журнала
  решений (`~/.octochan/decisions`) и синтетика из скиллов. Тестовый набор
  отложить до обучения.
- Цель: модель сама держится языка — маске и откатам почти нечего делать;
  на недостающую предпосылку — ⊥undef, а не догадка (H3).

**Шаг 4. Квантование и детерминированный вывод.** Квантовать (Q4/Q8) после
обрезки и LoRA; фиксированные параметры генерации, вычисления, не зависящие
от размера пачки (раздел 10 манифеста). Проверка: один вход — один ответ в
повторах.

**Шаг 5. Замер по разделу 9.2.** Условие 4 (встроенный режим со всеми
кольцами) против условий 1–3 (`natural`, формальный промпт без колец,
`protocol`): согласованность, правильность, доля ошибок вне отчёта, цена
колец.
