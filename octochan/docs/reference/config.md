# Настройки

`~/.octochan/config.yaml` (другой путь — `--config` или `OCTOCHAN_CONFIG`).
При первом запуске ochan создаёт его со значениями по умолчанию. Секретов
в нём нет и быть не должно — см. [переменные окружения](#переменные-окружения).

## Общее

| Ключ | По умолчанию | |
|---|---|---|
| `lang` | `ru` | язык справки и сообщений: `ru`, `eng` (`en`) или язык модуля; см. [«Язык интерфейса»](../guide/languages.md) |

## paths — каталоги узла

Каталоги, которые можно вынести из рабочего каталога (`~/.octochan`,
целиком он переносится указателем `ochan.home` рядом с программой или `OCTOCHAN_HOME`). Пусто — в рабочем каталоге. Путь
полный, `~` раскрывается; переменная окружения сильнее настройки.
Рабочему каталогу не по умолчанию, вынесенному каталогу и каталогам над ними
надёжнее принадлежать вам или root и быть закрытыми для записи группе и
остальным. Открытый каталог — не отказ, а предупреждение при запуске: его
выключает `paths.warn_open: false`. Что где лежит и что открыто — `ochan
paths`; подробно — [«Пути»](../guide/install.md#пути).

| Ключ | Окружение | По умолчанию | |
|---|---|---|---|
| `paths.modules` | `OCTOCHAN_MODULES` | `""` | модули (`*.hcplugin`) и пакеты алиасов; выносят туда, где хост разрешает запуск |
| `paths.logs` | `OCTOCHAN_LOGS` | `""` | журнал ochan и его архивы |
| `paths.reports` | `OCTOCHAN_REPORTS` | `""` | отчёты `ochan diff` |
| `paths.registry_cache` | `OCTOCHAN_REGISTRY_CACHE` | `""` | клоны git-реестров пакетов |
| `paths.warn_open` | — | `true` | предупреждать при запуске, что рабочий или вынесенный каталог открыт для записи группе или остальным (или чужой); `false` записывает и ответ «больше не показывать» в `ochan setup` |

## executors — исполнители модулей

Настройки исполнителя, которого принёс модуль, — под его именем:

```yaml
executors:
  rlm:
    api_url: https://rlm.example.internal/api/tasks.json
    http_timeout: 1m
```

Своего конфига у процесса модуля нет: ядро передаёт исполнителю в каждом
вызове `executors.<имя>` поверх общих `defaults.api_url`,
`defaults.http_timeout` и `defaults.max_parallel_tasks`. Токены сюда не
кладутся — `ochan auth --executor <имя>`. Подробнее —
[«Модуль-исполнитель»](../guide/modules.md#модуль-исполнитель).

## inventory — цели

Источники инвентаря — имя и адрес; схема адреса выбирает источник (`file` —
YAML-файл, путь без схемы — тоже файл). `~/.octochan/inventory.yaml`, если
он есть, — источник `local` без настройки.

```yaml
inventory:
  sources:
    main: /srv/inventory/hosts.yaml
    cmdb: file:///srv/cmdb/export.yaml
```

## triggers — роль по событию

```yaml
triggers:
  release:                       # имя: латинские строчные, цифры, _ и -
    event: ci/release            # что шлёт CI; по умолчанию — имя триггера
    grant:
      role: deployer             # какую роль открывает окно; не master и не llm
      scope: [group=prod]        # селекторы инвентаря: цели в окне; пусто — все
      max_window: 2h             # обязательно: 30m, 2h, 1d
```

Роль, названная в триггере, вне окна не может ничего, кроме общедоступного.
Секрет вебхука — `~/.octochan/triggers/<триггер>.secret` (`ochan trigger
secret`). Подробнее — [«Роли»](../guide/roles.md#по-событию-триггеры).

## llm — режим модели

| Ключ | По умолчанию | |
|---|---|---|
| `llm.mode` | `""` | `protocol` — модель внешняя (MCP), формальный промпт; `natural` — внешняя, естественный язык; `embedded` — своя модель ℒ: архитектурная, логика и кольца в её коде, в процессе ochan (`llm.model`) или по адресу (`llm.endpoint`); чужой движок по адресу ведёт декодер ochan (кольцо 0 и маска языка внутри генерации). Пусто — по `fp.mode` |
| `llm.engine` | `""` | что ожидается по адресу `llm.endpoint` (`ochan` у своей модели другой машины): сверяется с ответом `/v1/info` |
| `llm.model` | `""` | каталог своей модели (`ochan llm init`, веса — `ochan llm train`): команды загружают её в процесс ochan — словарь, сеть, логика и кольца; пусто — модель по адресу `llm.endpoint` |
| `llm.endpoint` | `http://127.0.0.1:8080` | без `llm.model` — адрес модели по протоколу движка v1 (своя модель другой машины — `ochan llm serve` там — или чужой движок); с `llm.model` — адрес, на котором её выставляет `ochan llm serve` |
| `llm.timeout` | `60s` | ожидание ответа модели по адресу |

`embedded` вместе с `fp.mode: natural` — отказ: своя модель знает только
формальный промпт. Подробнее — [«Своя модель»](../guide/embedded.md).

### Декодер ochan — для чужого движка

Своя модель ℒ их не читает: её параметры — `rings.json` рядом с весами
(`ochan llm fit`, `ochan llm learn`), а `ochan llm` предупреждает, если они
заданы не по умолчанию.

| Ключ | По умолчанию | |
|---|---|---|
| `llm.decoder.tau` | `0.42` | порог кольца 0: на позицию проходит не больше ⌊1/τ⌋ токенов |
| `llm.decoder.max_tokens` | `2048` | сколько раз спросить модель за ответ, с откатами |
| `llm.decoder.retries` | `32` | откатов к началу одного утверждения |
| `llm.decoder.derive` | `true` | выводимое из посылок пишет логика ochan (`fp.Derive`), модель только выбирает среди допустимых утверждений (`/v1/score`); `false` — решения пишет модель |

Прежние ключи — `llm.rings.tau`, `llm.max_tokens`, `llm.retries`,
`llm.derive` — читаются, пока нового нет в конфиге.

| `OCTOCHAN_ROLE` | роль для этого запуска — только роль без логина и пароля |
| `OCTOCHAN_REMOTE_LOGIN`, `OCTOCHAN_REMOTE_PASSWORD` | вход на сервер без вопросов (`connect`, `remote`) |

ochan-mcp для журнала аудита; `OCTOCHAN_SANDBOX_STAGE` — шаг процесса

журнал модулей.

## Сервер MCP

`ochan-mcp` настраивается флагами (`--root`, `--allow-live`, `--allow-env`,
