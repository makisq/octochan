# Эксперимент 9.2: стенд

Проверка формального промптирования по разделу 9 манифеста
([docs/formal-prompting.md](../docs/formal-prompting.md)). Здесь — задачи,
зафиксированные заранее параметры, прогоны и метрики.

## Условия

| № | условие | модель | подход | статус |
|---|---|---|---|---|
| 1 | естественный язык | внешняя | — | промпты готовы, модель не выбрана |
| 2 | формальный промпт с разбором, арбитрами и отчётом, без колец | внешняя | протокольный | промпты готовы, модель не выбрана |
| 3 | то же с кольцами 1–3 в режиме протокола | внешняя | протокольный | промпты готовы, модель не выбрана |
| 4 | своя модель ℒ, логика и кольца в её коде | `llama/own.py` | архитектурный | запускается |

В условиях 1–3 модель одна и та же — внешняя: в её код не попасть, язык и
кольца стоят вокруг неё. Её выбирает владелец; до тех пор `run.py run`
для этих условий отказывает с причиной.

## Предрегистрация

Всё ниже фиксируется до замера; меняется только новой версией плана.

- **Параметры** — [plan.yaml](plan.yaml): прогонов на запись — 3, τ = 0,42,
  well_True = 0,5, веса вопросов w(q) = 1 + n(q), версии модели для H4.
- **Гипотезы** H1–H7 — дословно из раздела 9.2; что опровергает подход —
  раздел 9.3.
- **План ответа** — пары «вопрос → ответ» X(I) из отчёта (А.5). Отказ без
  предпосылки — план «⊥undef».
- **Метрики** (`metrics.py`): ĉ — доля пар прогонов с одинаковым планом,
  на одной записи и между записями задачи (H1); p̂ — доля прогонов с
  задуманным планом I*; обе ещё градуированно, 1 − δ, δ — взвешенное
  расстояние Жаккара (А.5); H3 — отказ, а не догадка, на задаче без
  предпосылки; ошибки вне отчёта — решения ячеек ответа без записи в
  отчёте (H2); H4 — доля задач, план которых меняется при смене версии
  модели; H6 — калибровка выбора по журналу (`ochan fp journal export`);
  H7 — корреляция ĉ и p̂ по записям; цена — время, утверждения логики и
  выборы сети.
- **Разметка** — слепая: `metrics.py --blind` пишет планы без условия и
  модели в случайном порядке, ключ — отдельным файлом. Согласие
  разметчиков считается отдельно — когда их будет больше одного.

## Задачи

`tasks/*.yaml`, одна задача — файл:

| поле | что |
|---|---|
| `intended` | задуманный план I*: вопрос → ответ |
| `weights` | веса вопросов, посчитаны при подготовке |
| `natural` | пересказы на естественном языке — для условия 1 |
| `formal` | формальные записи: исходная и две равносильные (другой порядок отношений и правок, синонимы того же смысла) |
| `lacking` | записи без предпосылки — для H3 |

Сейчас задач 6 (из `llama/tasks`, без словарей скиллов), все — **черновики**:
эталон I* выведен логикой, пересказы написаны черновиком. Утверждает их
владелец. По манифесту задач около 50 — по СУБД, nginx, Kubernetes, Docker,
Linux; набор расширяется тем же форматом (`run.py prepare`).

## Первые результаты, 01.11.2026

Условие 4, четыре версии своей модели (`own-small` — первый словарь,
`own-small-2` — второй, int8 и int4 второй), 6 задач × 3 записи × 3
прогона и 6 записей без предпосылки — [results/report.md](results/report.md):

| метрика | все четыре версии |
|---|---|
| ĉ на одной записи | 1,000 (54 пары) |
| ĉ между записями (H1) | 1,000 (18 пар) |
| H3: без предпосылки — отказ | 1,000 (18 прогонов) |
| ошибки вне отчёта (H2) | 0,000 |
| H4: задач, план которых меняется между версиями | 0 из 6 |
| p̂ по эталону | 1,000 — см. ниже |

Что это значит и чего не значит:

- Для условия 4 эти числа получены **по построению**: выводимое пишет
  логика модели, её распределение переопределено, вывод детерминирован —
  ни повторы, ни перефразировки, ни смена весов (даже int4) план не
  меняют. Это и есть свойство архитектурного подхода, но не сравнение.
- **p̂ = 1 тавтологично**: эталон-черновик выведен той же логикой. Значимым
  он станет, когда эталон утвердит владелец.
- H6 по журналу — все исходы верные (имитатор оператора на синтетике):
  калибровать не на чем.
- H1, H2, H4 проверяются **сравнением** с условиями 1–3 на той же внешней
  модели, H5 — снятием колец по одному. Пока это не сделано, вывода по
  гипотезам нет.
